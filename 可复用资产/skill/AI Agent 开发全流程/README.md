# AI Agent 开发全流程

> 一套把「AI 写代码时代的工程纪律」固化成可执行流程的完整技能包。
> 骨架来自开源 [mattpocock/skills](https://github.com/mattpocock/skills)（22 万 star 的工程级 Agent Skills），
> 血肉来自本机 `可复用资产/` 多年积累的规则、MCP Server、技能与验收工具。

---

## 这是什么

一句话：**未来开发 AI Agent / AI 应用时，照这份流程走，不会踩 vibe coding 的坑。**

开源 mattpocock/skills 证明了四件事值得学：
1. 写代码前先「拷问需求」（Grill），治需求错位
2. 建共享词汇表（CONTEXT.md），治输出啰嗦、省 token
3. 强制 TDD 反馈环，治代码不工作
4. 定期架构收敛，治泥球越滚越大

这份技能把以上四点**翻译进你的资产体系**：每一阶段都映射到本机已有的规则、模板、MCP Server 和技能，
而不是让你另起炉灶。同时保留你的独有优势——**硬门禁**（`check_code_rules.py` + CI），
形成「提示词级流程引导 + 机器级硬门禁」双层约束。

## 七阶段一览

| # | 阶段 | 一句话 | 关键产出 |
|---|---|---|---|
| 0 | 路由判断 | 先判任务类型，选对走法 | 流程/技能选择 |
| 1 | 需求拷问 | 写代码前把需求/边界/异常/验收问清楚 | 四份待填写模板 |
| 2 | 词汇表+领域建模 | 建共享词汇，防跑偏省 token | CONTEXT.md |
| 3 | 架构决策 ADR | 不可逆决策先拍板再写码 | ADR 文档 |
| 4 | TDD 实施 | 小切片、每步自测、硬门禁 | 可运行切片+门禁通过 |
| 5 | 五阶段验收 | 用真实设施跑通五件套 | 验收报告 |
| 6 | 写后检查+交付 | 三检查点+验收清单+诚实报告 | 交付报告 |
| 7 | 架构收敛 | 定期扫设计压力，债不过夜 | 豁免名单/重构 |

## 怎么用

1. **从零开发**：让 Claude（或任一支持 skill 的 Agent）执行 `AI Agent 开发全流程`，从阶段 1 开始逐阶段走
2. **单点复用**：只是加个能力 / 排个 bug / 验个收，看 SKILL.md 阶段 0 的路由表，直接调对应技能
3. **评估存量 Agent**：按七阶段逐项检查差在哪一环，补缺口
4. **安装为可调用技能**（可选）：把本目录复制/链接到 Claude Code 的 `skills/` 目录，即可用 `/AI Agent 开发全流程` 唤起（本技能采用与其他技能一致的文件格式，安装方式参考你已有技能的接入习惯）

## 与现有资产的关系

```
可复用资产/
├── harness/                 # 规则与流程（本技能阶段的"制度依据"）
│   ├── 01-规则/             # 工作规则 / 编码安全 / 防熵机制
│   ├── 02-模板/项目骨架/     # 骨架 + check_code_rules.py 硬门禁
│   ├── 03-参考-项目经验/     # 架构分层 / 机制库 / 踩坑清单
│   ├── 04-待人类填写/        # 阶段 1 的产出模板
│   └── 05-执行流程/          # 验收清单 / 交付报告模板
├── MCP sever/               # 5 个可复用能力件（阶段 3/5 的标准件）
├── skill/                   # 本技能 + 5 个组件技能（阶段 0 路由的目标）
└── AI应用验收工具/           # 五阶段验收（阶段 5 直接调用）
```

本技能是**编排层**：不替代任何现有资产，而是把散落的资产按「开发一个 Agent 的顺序」串起来。

## 为什么值得用（而不是裸 prompt 或只装开源版）

| 对比 | 裸 prompt | 开源 mattpocock/skills | 本技能 |
|---|---|---|---|
| 工程纪律 | 无 | 有 | 有（同源） |
| 贴合你的 Python 技术栈 | - | 差（TS 导向） | 好（FastAPI/asyncpg/Redis/PG） |
| 可复用能力件 | 无 | 无 | 5 个 MCP Server 白捡 |
| 硬门禁 | 无 | 无（纯提示词级） | 有（check_code_rules.py + CI） |
| 与你的规则体系 | 无 | 无 | 深度映射（harness 全套） |

## 维护约定

- 流程随实战调整：先手动走几次，稳定后再改 SKILL.md（不要在没验证过就改流程）
- 新增可复用 MCP Server → 同步更新 SKILL.md「Agent 标准件清单」表
- 新踩的坑 → 写回 `../../harness/03-参考-项目经验/03-踩坑清单.md`，并在本技能相关阶段提一句
- 本技能本身遵守 `../../harness/01-规则/02-防熵机制.md`：单文件 ≤600 行、函数 ≤80 行、无 emoji、LF
