# 底层规则（任何任务必读，全程有效）

> **用途**：不分任务类型，只要在本流程内工作就必须遵守的最小纪律集——任务无关、语言无关。
> **何时用**：每次会话开始随 `../AGENTS.md` 一起读一次；与任务文件冲突时，**以更严格的为准**。
> **维护**：本文件是通用纪律的**唯一权威源**——新的通用坑加到这里，其他文件不再重复这些条款；
> 只跟某类任务相关的，加对应任务文件或支撑文件。需要完整背景 → 按 `../AGENTS.md`「细节下钻」索引读原文。

## 1. 需求与范围

1. **需求库是唯一依据**：只做需求库内的事；`[待定]` / 矛盾 / 凭据缺失 / 验收不清 → 停下问人，禁止猜测
2. **不顺手做事**：顺手优化、顺手重构 → 先登记，人确认后才做；需求库文件 AI 无权删改
3. **改前先读现状**：改动前先读目标文件当前内容，不覆盖他人改动；大改动先列清单

## 2. 复用优先

4. **动手前第一步**：先查仓库内是否已有同类实现，无再搜 GitHub / 开源仓库找健壮参考；能复用不重写
5. **借鉴不照抄**：能解释每行作用，改造为符合本项目分层/命名/规范，注明来源与许可证

## 3. 安全红线

6. **密钥禁硬编码**：统一走安全目录 `.env`；缺失必须 fail loudly（启动失败），禁止默认值兜底；`.env` 不进 git
7. **敏感信息不外泄**：日志/响应禁打印密码、Token、API Key、手机号、身份证号；DB 错误脱敏再透出
8. **输入不可信**：用户输入/上传/回调是信任边界，先清洗再进上下文；SQL 一律参数化
9. **破坏性操作先确认**：DELETE / 清表 / 覆盖 / 删除超过 1GB 文件，必须经人类确认；迁移有回滚路径

## 4. 过程纪律

10. **每步自测再进下一步**：本步测试没过不进入下一步；硬门禁必须过，禁止 `|| true` 跳过
11. **结构即纪律**：函数 ≤80 行、文件 ≤600 行，违规当场拆；非平凡逻辑留一个可运行检查
12. **诚实汇报**：没做的说没做，有风险的说风险；无自验证据不宣称完成；SKIP 必须说明原因

## 5. 人机分工

13. **信任边界人拍板**：鉴权/权限/密钥/资金/支付/数据库迁移/公开 API 契约/重构范围，必须人类确认后才动
14. **给选项不甩锅**：需要人决策时给 2-3 个方案并标注推荐；边界由人类定，AI 不擅自定
