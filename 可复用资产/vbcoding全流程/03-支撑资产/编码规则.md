# 编码规则（编码任务专属细化）

> **用途**：编码 / 修 Bug 任务的专属细化规范。通用纪律（需求范围 / 复用 / 安全红线 / 过程 / 人机分工）
> 以 `../00-底层规则/底层规则.md` 为**唯一权威源**，本文件不再重复，只保留编码专属条款。
> **何时用**：编码-prompt / 修复bug-prompt 指定加载时；审阅阶段对照核验。
> **适用**：任何语言/项目（Python/JS/Agent 通用；标「按项目选用」的项视技术栈取舍）。
> **细节下钻**：需要密钥体系 / 分层模型 / 迁移陷阱等完整背景 → 按 `../AGENTS.md`「细节下钻」索引读原文。

## 1. 代码质量

1. **每段代码/每个函数必须带注释**（做什么、为什么）；关键边界（锁/事务/幂等/安全）注释「为什么」
2. **禁止 emoji**（用户要求除外）；统一换行 LF
3. **命名**：文件/变量 `snake_case`（Python）或对应语言惯例；类 `PascalCase`；常量 `UPPER_SNAKE`
4. **函数单一职责**；类型标注必须有（参数与返回值）；docstring 写「做什么/入参/返回」
5. **分层**：业务逻辑禁止写进路由层；路由只做校验 + 调 service + 组装响应
6. **超限当场拆**：主流程只做编排，步骤拆私有函数（函数/文件行数限额见底层规则第 11 条）

## 2. 安全（编码附加项）

7. **SQL 参数化落地**：任何拼接途径都禁止（格式化字符串 / f-string / `+` 拼接 / ORM `text()` 裸语句）
8. **登录接口限流防撞库**；CORS 白名单不放开 `*`

## 3. 数据与并发

9. **数据库结构变更走迁移**（如 Alembic），禁止手工 ALTER
10. **表名/字段 snake_case**；必备 `created_at`/`updated_at`（UTC 存储）；资金/并发敏感表加版本号乐观锁
11. **事务**：写操作显式事务；锁 + 余额变更 + 流水必须在同一事务（杜绝账实不符）
12. **幂等**：唯一索引 + 幂等键；并发扣款 = 分布式锁 + 乐观锁双保险

## 4. 写完立即检查（防熵）

13. **写完立即检查**：结构（超限当场拆）、逻辑（分支/边界/空值/异常/并发/资源释放）、可读性（6 个月后能否看懂）
14. **重复 ≥3 处 → 抽公共函数**；历史债记豁免名单（理由 + 到期复审），不许过夜

## 5. 工程卫生

15. 提交前确认：无密钥、无调试残留、无无关文件；`.gitignore` 覆盖 `.env`/备份/临时文件
16. 提交信息 `type(scope): 描述`（feat/fix/refactor/docs/chore...）
17. 新踩的坑 → 追加到踩坑清单（`../../harness/03-参考-项目经验/03-踩坑清单.md`）

## 6. 审查前置补充（vbcoding 硬约束）

18. **成熟库优先**：业界有成熟库的能力（限流 / JWT / 健康检查 / 密码哈希 / ORM 迁移）**禁止手写底层**；
    用社区标准库（详见同目录 `ARCHITECTURE_RULES.md`），保持代码精干
19. **外部失败语义**：依赖外部服务（短信 / 邮件 / 发 Token）的操作失败，必须抛 5xx（如 `HTTPException(503)`），
    **严禁返回「成功」状态欺骗前端**
20. **输入防御**：JSON 接口用 Pydantic BaseModel + `Field(max_length=...)`；手写 `request.json()` 必须带 `limit`
    （完整自检清单见同目录 `边界约束.md` 第 7 节）
21. **机器门禁**：Python 项目 CI 必过 ruff（lint + format 一体，毫秒级）；安全敏感模块加 semgrep 规则扫描
    （审阅 L3 的机器化）。与项目自检 check_code_rules.py 并存：行业门禁 + 项目自检，缺一不可
