# 第一部分：基础面试题（100 道）

## 1.1 Python 基础（15 题）

**1. GIL 是什么？有什么影响？**
GIL（全局解释器锁）让同一时刻只有一个线程执行 Python 字节码。影响：CPU 密集型多线程无法并行；IO 密集型不受影响（等待时释放锁）。解法：多进程、协程、C 扩展。

**2. 深拷贝和浅拷贝的区别？**
浅拷贝只复制一层引用，内层对象仍共享；深拷贝递归复制全部，完全独立。`copy.copy` vs `copy.deepcopy`。

**3. 装饰器是什么？怎么用？**
不修改原函数就能给函数加功能的语法糖。`@decorator` 本质是 `func = decorator(func)`。常用于日志、鉴权、缓存、重试。

**4. 生成器和迭代器区别？**
迭代器是实现了 `__iter__`/`__next__` 的对象；生成器是特殊的迭代器，用 `yield` 惰性产出，不一次性占用内存（适合大文件/大流）。

**5. 可变对象和不可变对象？**
不可变：int、str、tuple、frozenset；可变：list、dict、set。函数传参时不可变按值、可变按引用——这是经典 bug 源。

**6. `*args` 和 `**kwargs`？**
`*args` 收位置参数为元组，`**kwargs` 收关键字参数为字典。用于写通用函数、参数转发。

**7. 什么是闭包？**
内层函数引用外层函数的变量，外层函数返回内层函数。用于装饰器、工厂函数、保留状态。

**8. `is` 和 `==` 区别？**
`is` 比较身份（内存地址），`==` 比较值。小整数缓存（-5~256）会让 `is` 结果反直觉，一般用 `==` 或 `is None`。

**9. `with` 上下文管理器原理？**
实现 `__enter__`/`__exit__` 的对象，`with` 保证退出时执行清理（关文件、释放锁）。`contextlib.contextmanager` 可快速自定义。

**10. 多线程、多进程、协程怎么选？**
IO 密集用协程（asyncio）或线程；CPU 密集用多进程；要分布式用多机。协程开销最小。

**11. asyncio 的事件循环是什么？**
单线程循环调度协程：await 遇到 IO 挂起协程，循环去执行别的协程，IO 完成再回来。适合大量 IO 等待。

**12. Python 垃圾回收机制？**
引用计数为主（计数归零立即回收）+ 标记清除（处理循环引用）+ 分代回收（按对象年龄分代，减少扫描）。

**13. 类方法、静态方法、实例方法区别？**
实例方法收 self；类方法收 cls（`@classmethod`）；静态方法无特殊参数（`@staticmethod`）。类方法常用于工厂。

**14. 列表推导式和生成器表达式？**
`[x*2 for x in lst]` 生成列表（立即占内存）；`(x*2 for x in lst)` 生成生成器（惰性）。大数据量用生成器。

**15. Python 慢怎么办？**
先 profile 定位瓶颈；用 `numpy`/`pandas` 向量化；CPU 密集用多进程/C 扩展/`numba`；减少循环里的 IO；缓存重复计算。

## 1.2 数据结构与算法（15 题）

**16. 数组和链表的区别？**
数组连续内存、随机访问 O(1)、插入删除 O(n)；链表离散、随机访问 O(n)、插入删除 O(1)。选择看读写模式。

**17. 哈希表冲突怎么解决？**
开放寻址（线性探测）、链地址法（链表/红黑树）。Python dict 用开放寻址。

**18. 栈和队列的应用？**
栈：括号匹配、函数调用栈、撤销；队列：任务调度、BFS、消息队列。

**19. 二叉树三种遍历？**
前序（根左右）、中序（左根右）、后序（左右根）。中序+前/后可重建树。

**20. 二分查找的前提和复杂度？**
有序序列，O(log n)。边界条件（mid 取整、左右指针）是易错点。

**21. 常见排序复杂度？**
快排/归并/堆 O(n log n)；冒泡/插入/选择 O(n²)；快排最坏 O(n²) 但平均最优；归并稳定且稳定 O(n log n)；计数/桶排序可 O(n)。

**22. 快排原理？**
选基准，分区（小的左边大的右边），递归。优化：随机基准、三数取中、小数组插入排序。

**23. 堆和优先队列？**
完全二叉树，父节点大于（最大堆）子节点。用于 TopK、定时任务、Dijkstra。Python 用 `heapq`（最小堆）。

**24. LRU 缓存怎么实现？**
哈希表（O(1) 查找）+ 双向链表（O(1) 移动/删除）。访问移到头部，满时淘汰尾部。你项目里的 `_LRUCache` 用 OrderedDict 实现。

**25. BFS 和 DFS 区别？**
BFS 用队列、层序、找最短路径；DFS 用栈/递归、深挖、找所有路径。

**26. 动态规划是什么？**
把大问题拆成重叠子问题，记录子问题答案避免重复计算。三步：定义状态、写转移方程、定初始条件。经典：背包、最长公共子序列、爬楼梯。

**27. 时间复杂度和空间复杂度？**
时间：操作次数随输入增长的量级；空间：额外内存的量级。面试先答复杂度再答实现。

**28. 字符串匹配常用？**
朴素 O(nm)、KMP O(n+m)（利用前缀表跳过）、Rabin-Karp（哈希）。

**29. 大数相加/相乘怎么做？**
用字符串/数组模拟竖式，逐位处理进位。考察基本功。

**30. 面试常考算法类型？**
数组双指针、滑动窗口、哈希、链表反转、二叉树、回溯、DP、TopK（堆）、二分。刷题按这 9 类覆盖。

## 1.3 操作系统（10 题）

**31. 进程、线程、协程？**
进程 = 资源隔离单位（独立内存）；线程 = 进程内执行单位（共享内存）；协程 = 用户态调度、单线程内并发。

**32. 死锁的四个必要条件？**
互斥、持有并等待、不可剥夺、循环等待。破坏任一即可避免。

**33. 虚拟内存和分页？**
进程看到连续虚拟地址，映射到不连续物理页，缺页时从磁盘调入。隔离 + 超量使用内存。

**34. 上下文切换是什么？**
CPU 从一个任务切到另一个，保存/恢复寄存器状态。频繁切换是性能杀手。

**35. select / poll / epoll？**
多路复用：select 轮询 fd（上限 1024）；poll 无上限但仍是线性扫描；epoll 事件驱动 O(1)，只返回就绪的。高并发服务用 epoll。

**36. 阻塞、非阻塞、同步、异步？**
阻塞 = 等结果才返回；非阻塞 = 立即返回未就绪；同步 = 调用方自己等；异步 = 完成通知回调。IO 模型四象限。

**37. 内存泄漏是什么？**
分配的内存无法回收。Python 里常见：全局缓存无限增长、循环引用未处理、未关闭资源。你的 LRU 有容量上限就是防这个。

**38. 用户态和内核态？**
用户态受限执行应用代码，内核态执行特权操作（IO、内存、系统调用）。切换有开销，所以减少系统调用。

**39. 信号量和互斥锁？**
互斥锁 = 同一时刻一个线程持有（0/1）；信号量 = 允许多个（N）。你项目里的 `Semaphore(5)` 限流就是信号量。

**40. 什么是零拷贝？**
数据不经用户态直接在内核间传输（sendfile、mmap），减少拷贝次数。高吞吐服务的优化点。

## 1.4 计算机网络（15 题）

**41. TCP 三次握手？**
SYN → SYN+ACK → ACK。确认双方收发能力，分配序列号。为什么不是两次：防旧连接请求误建连。

**42. TCP 四次挥手？**
FIN → ACK → FIN → ACK。为什么四次：TCP 全双工，两边各自关闭。TIME_WAIT 等 2MSL 防旧包干扰。

**43. TCP 和 UDP？**
TCP 可靠、有序、面向连接、有拥塞控制；UDP 不可靠、无连接、低延迟。视频/游戏用 UDP，业务用 TCP。

**44. 常见 HTTP 状态码？**
200 成功、301 永久重定向、302 临时、400 参数错、401 未认证、403 无权限、404 不存在、429 限流、500 服务端错、502 网关错、503 不可用、504 超时。你的限流返回 429。

**45. HTTP 和 HTTPS 区别？**
HTTPS = HTTP + TLS 加密。防窃听、防篡改、防冒充。握手用非对称交换密钥，传输用对称加密。

**46. 对称和非对称加密？**
对称（AES）：同一密钥加解密，快；非对称（RSA/ECC）：公钥加密私钥解密，慢但密钥安全分发。HTTPS 结合两者。

**47. 浏览器输入 URL 到显示的过程？**
DNS 解析 → TCP 连接 → TLS 握手 → HTTP 请求 → 服务器处理 → 响应 → 浏览器渲染。

**48. DNS 是什么？**
域名 → IP 的解析系统。层级：根 → 顶级域 → 权威。有缓存，TTL 控制。

**49. 负载均衡怎么做？**
DNS 轮询、L4（IP+端口）、L7（应用层，nginx）。算法：轮询、加权、least_conn、ip_hash。你的 nginx 是 L7 轮询。

**50. 反向代理 vs 正向代理？**
正向代理替客户端访问（翻墙）；反向代理替服务器接收（负载均衡、隐藏后端）。你的 nginx 是反向代理。

**51. Cookie、Session、Token？**
Cookie 客户端存；Session 服务端存（有状态）；Token 无状态（JWT）。Cookie 有跨域限制，Token 适合分布式。

**52. CORS 是什么？**
浏览器同源策略的放宽机制：服务器返回 `Access-Control-Allow-Origin` 允许跨域。你的中间件配了白名单。

**53. 什么是幂等？**
同一请求重复执行结果相同。GET/PUT/DELETE 天然幂等，POST 不幂等。支付要保证幂等（你做了状态机）。

**54. TCP 粘包/拆包？**
TCP 是字节流无边界。应用层要自己定协议（长度前缀、分隔符）。流式 SSE 用 `\n\n` 分隔。

**55. WebSocket vs SSE？**
WebSocket 全双工（双向、适合聊天/游戏）；SSE 单向服务端推送、基于 HTTP、自动重连、适合 LLM 流式输出。

## 1.5 数据库（15 题）

**56. 事务 ACID？**
原子性（全成全败）、一致性（约束不破）、隔离性（并发互不干扰）、持久性（提交不丢）。你的资金操作用事务保证原子。

**57. 隔离级别？**
读未提交、读已提交（PG 默认）、可重复读（MySQL 默认）、串行化。级别越高并发越差。幻读是"读到新插入的行"。

**58. 索引为什么用 B+ 树？**
B+ 树矮胖（扇出大、层数少）、叶子有序链表（范围查询高效）、非叶子只存索引（内存可装更多）。比二叉树更适合磁盘。

**59. 聚簇索引和非聚簇？**
聚簇 = 数据按索引顺序存（主键，叶子就是数据）；非聚簇 = 叶子存指针（回表）。InnoDB 主键是聚簇。

**60. 最左前缀原则？**
联合索引 (a,b,c) 能用 a、a+b、a+b+c，不能用 b 单独。查询要按索引顺序。

**61. 乐观锁和悲观锁？**
乐观锁：版本号/CAS，冲突重试，适合读多写少；悲观锁：`SELECT FOR UPDATE` 行锁，适合写多。你的支付双锁都用。

**62. 慢查询怎么优化？**
EXPLAIN 看是否走索引 → 加/调索引 → 优化 SQL（避免 `%xx%`、函数包字段、select *）→ 分页优化 → 必要时缓存/分库。

**63. 主从复制原理？**
主库写 binlog，从库 IO 线程拉取、SQL 线程重放。读写分离：读走从、写走主。有复制延迟。

**64. 分库分表？**
数据量大到单库扛不住：水平分表（按 id 哈希/范围）、垂直拆分（按业务）。引入分布式事务/跨库查询复杂度。单机阶段不需要。

**65. 缓存和数据库一致性？**
Cache Aside：先更库再删缓存；延迟双删；binlog 订阅（CDC）。强一致用"先更库 + 删缓存 + 短暂不一致可接受"。

**66. 连接池为什么必要？**
建连接贵；池化复用 + 上限保护。没有池 = 高并发下连接数爆炸打爆数据库。

**67. 三大范式？**
1NF 列不可分；2NF 消除部分依赖；3NF 消除传递依赖。实际项目以 3NF 为主，为性能可反范式（冗余）。

**68. EXPLAIN 关键字段？**
type（all=全表、ref/range 走索引、const 最优）、rows（预估行数）、key（用的索引）、Extra（Using filesort 要优化）。

**69. 数据库死锁？**
两个事务互相持有对方要的锁。解决：统一加锁顺序、锁超时、死锁检测回滚。你的支付按订单加锁，不同订单不冲突。

**70. Redis 常用数据结构？**
String（计数）、Hash（对象）、List（队列）、Set（去重）、ZSet（排行榜/滑动窗口）。持久化：RDB 快照 + AOF 追加。

## 1.6 大模型与 AI 基础（15 题）

**71. Transformer 核心是什么？**
Self-Attention 自注意力：每个 token 与其他 token 算相关性，捕捉长距离依赖；多头注意力从多角度学；位置编码注入顺序。

**72. Self-Attention 怎么算？**
Q（查询）× K（键）点积 → softmax 归一化 → 乘 V（值）加权求和。QKV 是输入的三个线性变换。

**73. Token 是什么？**
文本切分的最小单位，约半个汉字/3-4 字母。计费按 token。上下文长度 = 能塞的 token 数。

**74. 温度、Top-p、Top-k？**
温度调概率分布平滑度（越低越确定）；Top-p 从累计概率前 p 的候选里选；Top-k 从概率前 k 个里选。分类/法律用低温度。

**75. 上下文窗口是什么？**
模型一次能看的最大 token 数。超了要截断/压缩（你的记忆压缩就是这个）。

**76. 微调、RAG、Prompt 怎么选？**
Prompt 最快最便宜（改提示词）；RAG 接外部知识（知识更新、可溯源）；微调改模型行为（风格、领域），最贵。生产顺序：先 Prompt → RAG → 才微调。

**77. Embedding 是什么？**
把文本映射成高维向量，语义相近的向量距离近。用于检索、聚类、去重。你的知识库用 768 维向量。

**78. 向量数据库？**
存向量 + 近似检索（ivfflat、HNSW）。你用的是 PostgreSQL 的 pgvector 扩展，够用；量大了再上独立向量库（Milvus/FAISS）。

**79. 幻觉怎么治理？**
引用来源（RAG 带出处）、Rerank 精排、低温度、答案要求"不确定就说不确定"、引用逐条与已检索条文比对并在零召回时直接拒答。

**80. Function Calling 原理？**
把工具定义（名称+参数 schema）传给模型，模型返回"要调用哪个函数+参数"，代码执行后把结果喂回。你的工具调用就是这个。

**81. 流式输出原理？**
SSE 逐块推送。首 token 时间（TTFT）是关键指标。流式要断连取消（生产必备）。

**82. RAG 完整流程？**
文档切块 → Embedding 入库 → 查询向量化 → 召回（关键词+向量）→ Rerank → 组装上下文 → LLM 生成 → 带引用输出。

**83. 多 Agent 协作为什么好？**
单 Agent 会漏领域、上下文有限；多 Agent 分工 + 交叉审阅提升质量。代价是多次调用（成本/延迟），所以用路由分流。

**84. 大模型怎么评测？**
自动指标（检索侧 Recall@k / MRR）+ 人工标注问答集。当前口径是 190 条法条级标注集切 train / holdout，评测流量用独立 persona 真跑并与线上统计隔离。

**85. LLM 成本怎么控制？**
语义缓存（重复问题不重调）、意图路由（简单问题走轻量）、工具结果压缩（省上下文 token）、模型分级（简单用便宜模型）、token 用量告警。

## 1.7 项目深挖（15 题）

**86. 项目最大的亮点？**
一核双用可插拔架构：一套 Agent 引擎承载三个业务，新增领域不改核心代码——这是架构思维，不是堆功能。

**87. 遇到的最大困难？**
模型把"七天无理由退货"死归因到民法典，改 prompt 三版无效 → 用架构解法（法律映射表在 LLM 前拦截），CC019 从 2 分提到 7 分。体现"模型解决不了用架构绕"。

**88. 为什么自研 Agent 不用 LangChain？**
可控（工具/成本/调试全掌握）、轻量（不引入重依赖）、学习深度（能讲清 ReAct 原理）。对 LangChain 设计思想对标学习后自研。

**89. 并发容量你怎么评估的？**
没做过对外可复现的负载压测，早期 Locust 数字已作废。当前的容量约束是内存：1GB 单机上重排模型常驻约 1.1GB 会压穿内存并导致隧道 502，所以 lite 栈四个服务分别钉死内存上限合计 704MB、重排默认关闭。要谈并发数，得先定观测口径和样本量，否则数字没有意义。

**90. 怎么防 LLM 注入？**
Agent 上下文和上传内容都做指令注入过滤（`_sanitize_context` / `_sanitize_uploaded_content`）；敏感词 DFA 过滤。

**91. 支付并发安全怎么保证？**
分布式锁管进入 + 乐观锁管数据 + WAL 流水可对账；幂等靠订单状态机。最近还修了三个并发 bug（锁误删、扣费不查冲突、无重试）。

**92. 为什么限流用 Redis？**
多实例计数必须全局一致；Redis INCR 原子；计数器带 TTL 自清理。

**93. 三级缓存为什么这样设计？**

**94. 熔断什么场景触发？**

**95. 人格怎么切换？**
人格 = 配置包（人设 Prompt + 工具注册表 + 模型策略），`persona_manager` 按 `persona_id` 加载，核心引擎不动。

**96. CI/CD 怎么做？**

# 第二部分：RAG 与 LLM 深挖

## 2.1 向量化（Embedding）原理

**是什么**：Embedding 模型把文本映射成高维向量（768/1024/1536 维），语义相近 → 向量夹角小（余弦相似度高）。

**为什么有效**：语言模型在向量空间里学到了"语义位置"——"离婚"和"婚姻解除"距离近，和"天气"距离远。所以能语义检索，而不只是字面匹配。

**相似度计算**：
- 余弦相似度（最常用）：`cos = A·B / (|A||B|)`，范围 [-1,1]
- 点积 / 欧氏距离

**你的项目**：`knowledge_chunks.embedding vector(768)`，用 Embedding API 生成，`ivfflat` 索引做近似检索。

**面试常问**：为什么向量能语义匹配？答：模型训练时把共现/上下文相近的词映射到相近区域，向量距离近似语义距离。

## 2.2 Embedding 模型对比

| 模型 | 维度 | 特点 |
|---|---|---|
| text-embedding-3-small | 1536 | OpenAI，通用，性价比高 |
| text-embedding-3-large | 3072 | 更准更贵 |
| BGE（bge-m3） | 1024 | 中文强、多语言、免费开源 |
| shaw/dmeta-embedding-zh | 768 | 中文专用（你的本地/备用方案） |

**选型原则**：中文场景优先中文模型；维度决定存储成本（768 vs 1536 内存差一倍）；离线场景用开源（BGE）；API 场景用商业。

## 2.3 RAGAS 指标详解

RAGAS 是 RAG 系统的评估框架，核心三指标：

| 指标 | 测什么 | 怎么算 | 对应你项目 |
|---|---|---|---|
| **答案相关性**（Answer Relevancy） | 回答是否答到点上，不跑题 | 生成问题的反向问题与回答的相关性 | 回答是否覆盖用户问题 |
| **答案正确性**（Answer Correctness） | 回答事实是否与标准答案一致 | 与参考答案的语义/事实比对 | 法律答案与法条是否一致 |
| **忠诚度**（Faithfulness） | 回答是否忠于检索到的资料，不编造 | 回答中的每个论断能否在上下文中找到依据 | 有没有幻觉/编法条 |

**当前口径**：检索侧用 190 条人工标注集评 Recall@k 与 MRR（重排开启时 holdout Recall@5 93.0%、MRR 0.879，自测）；早先的 RAGAS 忠诚度 99.92%、相关性 99.33% 口径已作废，不要再引用。

**为什么忠诚度最重要**：RAG 的承诺是"有据可依"。忠诚度低 = 模型在编 = 法律/金融场景是事故。

## 2.4 幻觉治理清单

| 手段 | 原理 | 你的实现 |
|---|---|---|
| 引用来源 | 回答带出处，可验证 | 法条引用 |
| Rerank 精排 | 提高送入 LLM 的资料质量 | DeepSeek Rerank |
| 低温度 | 减少随机发挥 | 法律场景温度低 |
| 诚实约束 | prompt 要求"不确定就说不确定" | 人格规则 |
| 跨法域映射 | 纠正模型顽固错误归因 | 法律映射表 |
| 监控 | faithfulness 指标持续测 | RAGAS |

**面试答法**：幻觉无法 100% 消除，治理思路是"降低 + 可追溯 + 监控"三管齐下。

# 第五部分：2026-08 新增（MCP / LangGraph / eval / 重构）

## 5.1 MCP（模型上下文协议）

**一句话定义**：把 AI 能力协议化的标准——Host（应用）通过 Client 连接 Server，用 Tool 执行动作、Resource 读数据、Prompt 复用模板；传输分 stdio（本地）与 Streamable HTTP（远程）。

**核心概念**：
- 三原语：Tool（原子动作）/ Resource（可读数据）/ Prompt（复用模板）
- 价值三层：解耦（能力资产化）、组合（可被任意编排）、生态（一次接入到处用）
- 封装边界：一个 Tool = 一个语义动作；编排逻辑（多 Agent 圆桌）留 Host；领域知识下沉 Server

**30 秒话术**：
> "我把网关的 RAG 检索封装成了 MCP Server。封装时三个决策：检索拆成原子 Tool 而不是黑盒流程；法律映射等领域知识下沉 Server；Rerank 阈值收在内部只暴露 top_k 参数。过程中发现并修复了知识库构建脚本的正则缺陷（千位以上条号漏导），法条从 861 补全到 1260 条。"

## 5.2 LangChain 与 LangGraph

**分层关系（高频题）**：LC 是组件层（模型/工具/检索/记忆的零件库），LG 是编排层（状态图：State/Node/Edge/Checkpointer）——不是竞争，是垂直堆叠；LG 节点内部用 LC 零件。2024.10 起 LangChain 官方把 Agent 主推 LangGraph。

**核心概念**：State（TypedDict 共享状态）/ Node（阶段函数）/ Edge（流转）/ 条件边（分支）/ Checkpointer（持久化断点恢复）/ Human-in-the-loop（人工介入）。

**与自研对照**：我的 `AgentOrchestrator`（三阶段圆桌）在 LG 里 = 一个线性子图；`run_agent_task` 的 ReAct 循环 = 带条件回环的图。自研 = "流程即代码"，LG = "流程即数据"（可编译/可视化/断点恢复）。

## 5.3 eval-as-code（AI 质量工程）

**三种评测**：规则（关键词/格式）、LLM-as-judge（强模型打分+理由）、指标（RAGAS 忠诚度/相关性/正确性）。

**四要素**：用例集（版本化）→ 评分器（自动打分）→ **阈值门禁**（低于红线 = 失败）→ **回归对比**（与上次比，抓劣化）。

**线上闭环（进阶，加分项）**：用户点赞/点踩/追问 → 收集薄弱问答 → 补用例/调 prompt/补知识 → 下一轮回归验证。上线前评测是门槛，线上反馈闭环才是持续优化引擎。

## 5.4 工程约束与重构（Ponytail）

**约束三层**：规则文件（AGENTS.md/.cursorrules 给 AI）→ 自动检查（AST 扫描函数行数/静默异常）→ 审查闭环（AI 自查清单）。

**核心原则**：最好的代码是没写的代码（YAGNI → 复用 → 标准库 → 最小实现）；根因修复（修共享函数一次，不逐调用方打补丁）；删除优于添加；非平凡逻辑留一个可运行检查。

**实战故事**：重构 v2.py 时抽出 `stream_utils` 公共层（4 处流式调用/4 处工具分发/3 处文件注入/19 处 SSE 收敛），发现并修复了一个端点里的隐藏 NameError bug。
