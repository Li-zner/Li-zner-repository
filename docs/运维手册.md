## 一、SLI / SLO 定义

| 维度 | SLI（怎么测） | SLO（目标） | 对应告警 |
|------|--------------|------------|---------|
| 可用性 | 5xx 占比（`gateway_requests_total`） | 错误率 < 1%（月度） | HighErrorRate |
| 延迟 | p95（`gateway_request_duration_seconds`） | p95 < 5s | P95LatencyHigh |
| 体验 | 首 token 时间（`requests.first_token_time`） | p95 < 3s | 人工观测 |
| 成本 | 每万 token 花费（`llm_tokens_total` × 10 元） | 日 < 50 元 | LLMTokenSpike |
| 缓存 | 语义缓存命中率 | > 30% | CacheHitRateLow |
| 容量 | 并发处理能力 | 4 实例 × 200 = 800 并发近零错误 | 容量基线 |

**达成条件（全部满足才算健康）**：5 分钟 5xx < 5%；p95 < 10s；实例 healthy；
Prometheus `up=1`；缓存命中 > 10%。

## 二、容量基线与伸缩

- 单实例 ~200 并发；整系统 800 并发近零错误（Locust 实测）。
- 自动伸缩（`scripts/autoscale.sh`）：高>40 QPS / 低<12，min=1 max=4，
  interval=30s，cooldown=60s，连续 up-hits=3 / down-hits=6。
- **nginx upstream 必须与运行实例同步**（autoscale 维护 + `reconcile` 子命令；
  Docker DNS 不解析已停服务，残留会导致 reload 失败/请求挂起）。

| 扩容触发 | 阈值 | 动作 |
|---|---|---|
| CPU（网关容器） | > 70% 持续 5 分钟 | 加实例 |
| 并发计数 | 接近 200/实例 | 查滥用 or 扩容 |
| P95 | > 5s | 查 LLM/DB，非扩容 |
| Redis 内存 | > 80% | 检查缓存清理 |

## 三、备份现状

- 备份目录：`backups/`（`gateway_db_YYYYMMDD_HHMMSS.sql`，pg_dump 文本）
- 脚本：`scripts/backup_db.sh`（建议每天 cron）
- 持久数据：安全目录 `/etc/agent_gateway/.env`（WSL，root:root 644）、`static/`（已入库）
- RPO：每天备份 = 最多丢 1 天数据；RTO：目标 < 30 分钟

## 五、真实故障恢复流程

### 场景 A：单个网关容器挂了
```bash
# Docker HEALTHCHECK 会自动重启；或手动
docker compose up -d --force-recreate gateway
bash scripts/autoscale.sh reconcile   # 同步 nginx upstream
```

### 场景 B：全部容器挂（机器重启）
```bash
bash start_all.sh   # 单实例 + Nginx + autoscaler（幂等、基础设施容错）
# 验证
curl -s http://localhost:10090/health
```

### 场景 C：数据库损坏/误删
```bash
# 1. 停写入
docker compose stop gateway gateway2 gateway3 gateway4
# 2. 保留现场 + 恢复备份
docker exec postgres pg_dump -U agent_user -d agent_gateway > backups/gateway_db_crash_$(date +%Y%m%d_%H%M%S).sql
docker exec postgres psql -U agent_user -d postgres -c "DROP DATABASE agent_gateway"
docker exec postgres psql -U agent_user -d postgres -c "CREATE DATABASE agent_gateway"
docker cp backups/gateway_db_最新.sql postgres:/tmp/restore.sql
docker exec postgres psql -U agent_user -d agent_gateway -q -f /tmp/restore.sql
# 3. 拉起并验证行数
```

### 场景 D：`.env`/配置丢失
- 权威源：`/etc/agent_gateway/.env`（WSL）；桌面快捷方式「Agent网关配置.env.lnk」
  以管理员记事本打开编辑。改完需 `docker compose up -d --force-recreate gateway`。
- 从 `.env.example` 重建并填入密钥；**改密码后必须全链路探活**（登录→钱包→支付）。

## 九、生产补缺落地（2026-08-11）

### 慢查询监控
- 前置：postgres 已加载 `shared_preload_libraries=pg_stat_statements`（compose command），
  数据在命名卷 `agent_gateway_postgres_data`，重建不丢数据。
- 检查：`python scripts/slow_query_monitor.py --check --threshold 1000`
  （发现慢查询 exit 1，可接 cron 告警）；`--loop --interval 60` 常驻。
- 启用脚本：`bash scripts/enable_pg_stat_statements.sh`（幂等）。

### 备份与恢复演练
- 备份：`bash scripts/backup_db.sh` → 项目 `backups/gateway_db_*.sql`（保留 7 天）。
- 演练：`bash scripts/restore_drill.sh`（恢复临时库 + 校验 7 张核心表行数 + 清理）。
- **2026-08-11 实测通过**：users 102 / requests 561 / memories 1846 / chunks 875 /
  orders 524 / semantic_cache 29 / wallets 162，全部与生产一致。
- RPO=备份频率（默认每天）；RTO 目标 < 30 分钟。

### JWT 密钥轮换（双 Key 并行期）
- 脚本：`bash scripts/rotate_jwt_secret.sh`（rotate / --dry-run / --check / --remove-old）。
- 流程：新 JWT_SECRET + 旧值保留为 JWT_SECRET_OLD → 重建网关 → 并行期旧 token 仍可验
  → 旧 token 全过期后 `--remove-old` 再重建。
- **2026-08-11 实测通过**：旧 token 200 / 新登录 200。
- 坑：env 文件尾部无换行时追加会拼行（脚本已加保护）。
