# 防熵机制（写后检查 + 四道防线）

> 原则：**债不过夜**。背景：v2.py 从 150 行长到 700 行——10 次各自合理的追加，
> 每次都没人回头收敛。写完立即检查是唯一能在熵累积前拦截的机制。

## 一、写后检查（每次工作结束必做，不是次日审查）

### 检查点 1：结构合规（写完立即查，过不了不交付）
- 本次新增/修改的**每个函数 ≤ 80 行；每个文件 ≤ 600 行**。
- 违规 → **当场重构**（主流程只做编排，步骤拆私有辅助函数；文件超限拆模块）。
- 禁止「先跑通，以后再改」——新增违规不豁免，不许过夜。
- 历史债（既有超限函数/文件）不阻塞本次工作：记录进豁免名单，专项重构时处理；
  豁免只覆盖既有代码，本次新增的照样受约束。

### 检查点 2：逻辑与质量（写完逐项自查）
- 正确性：分支、边界、空值、异常路径全覆盖？
- 并发：共享状态无竞态？异步无阻塞调用？锁/事务正确？
- 错误处理：可恢复错误返回结构化 `{"error": ...}`？无静默吞异常？
- 资源：连接/文件/任务释放？外部调用有超时与取消路径？
- 重复 ≥3 处 → 抽公共函数；信任边界（用户输入/上传/回调）有校验？

### 检查点 3：质量足够高才交付
- 判断标准：**6 个月后别人改这段代码，能否快速看懂？** 答不上来 → 简化或询问。
- 非平凡逻辑（分支/循环/解析/资金/安全）留**一个可运行检查**（assert 自检/小测试）。
- 三检查点结论（✓/✗ + 遗留说明）写入交付报告。

## 二、四道防线（防再犯，按强度排序）

| 防线 | 机制 | 落地 |
|---|---|---|
| ① 结构防线（最强） | **引擎 + 配置分离**：业务差异（人设/工具/提示词/通道）= 配置包；新功能默认加配置，**动核心需人类批准**——上帝函数在结构上无处可放 | 新项目第一版就坚持 |
| ② 写后检查 | 见上文，债不过夜 | 本文件 |
| ③ 机器门禁 | `scripts/check_code_rules.py`（纯 AST 零依赖）接入 CI，违规发布失败；**新项目模板自带**（`02-模板/项目骨架/scripts/`），第一天就有闸门 | 模板已含 |
| ④ 人的节奏 | 每完成 5 个功能或每 2 周安排 1 小时收敛（查重复/超行/散落/文档过期）；人每周抽查交付报告的检查结论是否真实；架构变更必须同步架构文档 | 人执行 |

## 三、失败模式与对策（预案）

| 失败模式 | 征兆 | 对策 |
|---|---|---|
| 规则疲劳 | 报告出现「遗留：函数 120 行，下次拆」 | 人抽查 + 重构窗口收紧 |
| 豁免滥用 | 豁免名单持续扩大 | 豁免必须写理由 + 到期复审 |
| 配置层变质 | 配置开始含逻辑（if/循环） | 配置只允许数据；发现逻辑打回 |
| 检查器被绕过 | CI 被跳过/注释 | 门禁放 CI 强制步骤，禁止 `|| true` |
