# 选型清单——AI 应用工程开源项目（2026-09-05 星数实测）

> **用途**：按"构建 agent 全链路"的每个环节给出高星开源项目与取用建议。
> **规则**：星数经 GitHub API/页面实测；取用后仍须遵守本库编码规范；选型前重测星数。

## 一、Agent 框架（编排层）

| 项目 | 星数 | 定位 | 取用建议 |
|---|---|---|---|
| langchain-ai/langchain | 145,647 | LLM 应用全家桶（链/集成/工具） | 生态最全；新项目建议只用其集成层，编排用 LangGraph |
| langchain-ai/langgraph | 41,061 | 图状态机编排（可控、可回环、人机协同） | 生产级多步 agent 首选；自带 checkpoint 持久化 |
| crewAIInc/crewAI | 58,090 | 角色化多代理协作 | 团队分工型任务（研究员+写手+审校）快速原型 |
| microsoft/autogen | 60,801 | 多代理对话/事件驱动框架（企业级） | 微软系；研究型多代理与代码执行场景 |
| openai/openai-agents-python | 29,195 | OpenAI 官方轻量 Agents（handoff/工具/守卫） | 想要最薄编排层、官方长期维护 |
| huggingface/smolagents | 29,157 | 极简代码代理（~千行核心，code action） | 学习 agent 内核原理的第一读物 |
| pydantic/pydantic-ai | 19,728 | 类型安全 agent 框架（Pydantic 校验贯穿） | 重结构化输出与类型防御的项目——与本库"输入防御"红线同思想 |

**选型心法**：先问"要不要可控状态机"。要 → LangGraph；要多角色对话 → CrewAI/AutoGen；
要最薄且官方 → openai-agents；要类型安全 → pydantic-ai。不要一上来就全家桶。

## 二、RAG 框架与平台

| 项目 | 星数 | 定位 | 取用建议 |
|---|---|---|---|
| langgenius/dify | 154,461 | 可视化 LLM 应用平台（RAG+workflow+agent） | 团队要低代码编排/快速上线时；深度定制受平台约束 |
| langflow-ai/langflow | 154,255 | 可视化流程编排（拖拽式） | 原型演示与教学；生产建议导出为代码 |
| infiniflow/ragflow | 90,053 | 深度文档理解 RAG 引擎（版式解析+引用溯源） | 企业文档问答（合同/报告等复杂版式）直接用 |
| run-llama/llama_index | 52,022 | 数据框架（索引/检索/查询引擎抽象） | 自建 RAG 的数据层首选，比裸写省一半代码 |
| QuivrHQ/quivr | 39,495 | "第二大脑"文档问答 | 个人知识库场景参考 |
| Cinnamon/kotaemon | 25,731 | 开源 RAG UI（引用可视化干净） | 前端交互参考 |

**自建 vs 平台**：要可控（自建检索逻辑、接自有网关）→ llama_index/LangChain 自建；
要快（非开发者配置）→ Dify/RAGFlow。本库 `MCP sever/知识库双通道检索` 即自建路线的沉淀。

## 三、记忆（Memory）

| 项目 | 星数 | 定位 | 取用建议 |
|---|---|---|---|
| mem0ai/mem0 | 64,710 | 记忆层（抽取/更新/检索用户记忆） | 跨会话个性化记忆直接用；自建可参考其抽取-合并策略 |

轻量替代：会话内记忆用滑动窗口+摘要（参考 agent_gateway 的 memory_manager），
跨会话再上 mem0——不要第一步就引入重依赖。

## 四、模型网关与路由

| 项目 | 星数 | 定位 | 取用建议 |
|---|---|---|---|
| BerriAI/litellm | 58,049 | 统一网关（100+ 模型同一 OpenAI 接口、预算、降级） | 多模型切换/预算控制直接用；自己造网关前先看它 |

本库对照：`MCP sever/JWT令牌签发与校验`、`可复用代码/Token预算守卫` 覆盖其预算子集；
需要"多供应商路由"再上 litellm。

## 五、评测（Eval）——AI 应用工程师的分水岭

| 项目 | 星数 | 定位 | 取用建议 |
|---|---|---|---|
| langfuse/langfuse | 34,205 | LLM 可观测平台（trace/数据集/评分，开源自托管） | 生产必备；trace 先行，评测其次 |
| explodinggradients/ragas | 15,621 | RAG 评测指标（忠实度/答案相关性/上下文精度） | RAG 上线前必测三件套 |
| Arize-ai/phoenix | 11,329 | trace + eval（OpenTelemetry 原生） | 已有 OTel 基建时选它 |

**纪律**：没有评测集就不算完成 RAG/agent——上线前用真实问句建 20-50 条评测集，
ragas 跑分 + 人工抽检，达标线写进需求库验收标准（对接本库 vbcoding 验收流程）。

## 八、全链路怎么串（30 秒版）

```
文档 → MinerU 解析 → 切分 → pgvector 向量化 → 混合检索 + 重排   ← RAG 构建（见 RAG构建.md）
                                                              ↓
用户 → 网关(litellm/自有) → agent(LangGraph/pydantic-ai) → 工具(MCP) → 回答
         ↑ 记忆(mem0/自建)      ↑ 预算(Token预算守卫)      ↑ 锁/限流/熔断(可复用代码)
                                                              ↓
              可观测(langfuse trace) → 评测集(ragas) → 迭代（回到 vbcoding 需求库）
```

每一步的"为什么与坑"见 `agent全链路.md` 与 `RAG构建.md`。
