# RAG 构建链路（从文档到可信回答）

> **用途**：构建生产级 RAG 的完整链路——每环给"怎么做、怎么选、坑在哪"。
> **何时用**：任何"让 AI 回答私有知识"的需求；与 `agent全链路.md` 的评测/部署章节配合。
> **关系**：本库 `MCP sever/知识库双通道检索` 是本链路"检索层"的已验证实现，先读它再动手。

## 0. 全链路总览

```
文档 → 解析 → 清洗 → 切分 → 向量化 → 入库(pgvector)
                                        ↓
问题 → 改写 → 混合检索(向量+关键词) → 重排 → 组装上下文 → 生成 → 引用溯源
                                        ↓
                              评测(ragas 三件套) → 迭代
```

**铁律**：RAG 的上限由「解析与切分质量」决定，而不是模型——检索不到，模型再强也是编。

## 1. 解析（决定上限的一环）

- PDF/扫描件/复杂版式：MinerU（约 7.9 万星，中文强，版式/表格/公式还原好）；
- 多格式（html/pptx/eml）：unstructured（约 1.5 万星）；
- **坑**：直接 PyPDF 提取纯文本会丢表格结构与标题层级，下游切分全乱——
  表格转 markdown、标题转元数据，钱要花在这一环；
- 验收方式：随机抽 10 页，肉眼对比"解析出的 md"与原件，信息无损才算过。

## 2. 清洗与切分

- 清洗：去页眉页脚/水印/重复行；保留标题路径作为每块的元数据（如 `第三章 > 第二节`）；
- 切分参数起点：块 300-500 token、重叠 10-15%；**按结构切优于按长度切**
  （标题/段落边界优先，句子中间切断是大忌）；
- 元数据三件套必带：`source`（文件名/页码，引用溯源用）、`title_path`（层级）、`chunk_index`；
- **坑**：问答对/表格类内容按语义整块切，不要硬切。

## 3. 向量化（Embedding）

- 选型：中文用 bge-m3 / qwen3-embedding 级别的开源模型（自托管）或 API；维度与库对齐；
- **约定即资产**：模型名与维度写进配置与迁移注释——换模型 = 全库重算，
  必须建新列双写迁移，禁止原地覆盖（对接本库红线"数据库变更走迁移"）；
- 批量写入用 upsert + chunk_key（内容 hash）幂等，文档更新不重复入库。

## 4. 检索（决定下限的一环）

- **混合检索是默认项**：向量（语义）+ BM25/全文（关键词，专名/型号/法条号靠它）；
  两路各取 top-k 再融合（RRF）——单路向量检索在专名查询上必丢；
- 过滤先行：能用的元数据过滤（租户/分类/时间）在检索前收窄，别靠召回后丢弃；
- 参考实现：本库 `MCP sever/知识库双通道检索/pg_rag_search_server.py`
  （向量 + 全文双通道，踩坑清单 #28/#29 的教训都在里面）；
- **坑**：chunk_key/md5 幂等去重、清理时"保留带 embedding 的"——数据脚本必须可全量重跑。

## 5. 重排（Rerank，性价比最高的一环）

- 两阶段：先粗召回 top 20-50，再交叉编码器精排取 top 3-5 进上下文；
- 模型：bge-reranker 系列自托管，或供应商 rerank API；
- **坑**：不重排的 RAG 在"多文档相似主题"场景召回排序基本靠运气；
  上下文块数贪多反而掉点（lost in the middle），3-5 块为起点做实验。

## 6. 生成与引用溯源

- 提示词三要素：只依据给定材料回答 / 引用块编号标注来源 / 材料不含答案时明确说"未找到"；
- 引用回链：回答中的 [1][2] 映射到 source（文件+页码）——用户可验证，幻觉自然被压制；
- **坑**：把"未找到"兜底话术写进缓存或让缓存吞掉它（agent_gateway cache_warmup 的教训，
  见 `../可复用代码/README.md` 问题清单）。

## 7. 评测（ragas 三件套 + 线上闭环）

| 指标 | 测什么 | 不达标的病灶 |
|---|---|---|
| 忠实度 faithfulness | 回答是否被检索内容支撑 | 低 → 生成端幻觉，收紧提示词或加引用约束 |
| 答案相关性 | 回答是否切题 | 低 → 检索跑偏，查改写与混合检索 |
| 上下文精度/召回 | 该找到的找到没有 | 低 → 切分/嵌入/重排的问题，回 1-5 环排查 |

- 评测集：真实问句 30-50 条 + 期望来源；进 git，每个 bad case 转新用例；
- 流程：改任何一环 → 跑评测 → 全绿才上线（对接 vbcoding 收敛循环）。

## 8. 进阶路线（按需，不是必做）

- 查询改写：多轮对话先把指代补全再检索；复杂问题拆子查询；
- 语义缓存：重复问法直接命中（本库 `MCP sever/语义缓存`，注意个性化上下文维度隔离）；
- Agentic RAG：检索作为工具交给 agent 多轮调用（先证明单轮不够再上）；
- 图谱增强：实体关系明显的领域（法条/医药）再考虑 GraphRAG，成本高、别为技术而技术。

## 9. 检查单（上线前逐项过）

- [ ] 抽检 10 页解析无损；表格/标题进元数据
- [ ] 切分带 source/title_path/chunk_index；chunk_key 幂等可重跑
- [ ] 混合检索（向量 + 关键词）+ 重排已启用
- [ ] 回答带引用可回链；"未找到"路径验证过
- [ ] ragas 三件套有基线分；评测集进 git
- [ ] 缓存穿透/占位语义验证过（__EMPTY__ 不会当答案返回）
- [ ] 嵌入模型与维度已版本化记录，迁移有双写方案
