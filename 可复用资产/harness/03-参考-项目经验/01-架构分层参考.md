# 架构分层参考（来自 agent_gateway 实战）

> 注意：本目录是**参考**，不是规则。规则在 `01-规则/`。新项目按需借鉴，不必照搬。

## 参考架构

```
接入层     Nginx（WAF + 限流 + 负载均衡 + 静态）
网关层     认证 JWT / 限流 / 熔断 / 幂等键 / 请求日志 / 脱敏
业务层     services（事务/锁/状态机）+ Agent 引擎
数据层     PostgreSQL（pgvector/pg_trgm）+ Redis
可观测     Prometheus / Grafana / Loki / Tempo / Alertmanager
```

## 已验证的取舍

| 决策 | 为什么 |
|---|---|
| 业务逻辑不进路由层 | 路由只做校验+组装，逻辑集中可测试 |
| 密钥无默认值 | 缺失即启动失败，避免带病上线 |
| 数据库迁移用 Alembic | 版本可追踪、可回滚 |
| 容器内互访用服务名 | 不依赖 IP，弹性伸缩不受影响 |
| SSE 必须 proxy_buffering off | 否则流式被缓冲延迟 |
| 多实例 + Nginx | 单实例吞吐有限，Nginx 摘除故障实例 |

## 参考指标

- 单网关（asyncio 单 worker）约 300 QPS（/health 356，业务接口 250-280）。
- 多实例 + Nginx 轮询可线性扩展；并发 200+ 后单 worker 吞吐下降（需加实例）。
- Redis 锁 TTL 10s、乐观锁重试 3 次、限流阈值按接口分级。
