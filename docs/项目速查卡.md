## 二、主链路走读（3 条，能讲到「文件.函数」级）

### 链路 1：登录（认证）
```
Client → Nginx(10090, auth_limit 限流) → gateway(10092)
→ middleware/auth.py: authenticate_user() 校验用户名+密码(pwd_context)
→ create_access_token() 用 JWT_SECRET 签发
→ 返回 token；后续请求经 get_current_user() 校验 Bearer
```
- 关键点：登录接口严格限流防撞库；密钥来自环境变量无默认值。

### 链路 2：聊天流式（核心业务）
```
POST /v2/chat/stream
→ 中间件：认证 → 限流 → 熔断
→ app/services/chat_stream_core.py chat_generate():
    1. law_mapping.py 前置检查（法律映射表，命中直接引导，不调 LLM）
    2. core/semantic_cache.py 三级缓存（L0内存→L1 hash→L2 pg_trgm，阈值0.85）
    3. agents/router.py 意图路由（简单→单 Agent；复杂→orchestrator 圆桌）
    4. DeepSeek API（deepseek-v4-flash）流式生成
    5. SSE 流回（proxy_buffering off）
→ 对话结束后 payment/service.py deduct_token_cost() 异步扣费（10元/万token）
```
- 关键点：缓存先于 LLM（省钱）；断连即取消上游任务（防泄漏）。

### 链路 3：支付扣款（并发安全核心）
```
deduct_token_cost() (service.py:443)
→ ensure_wallet_exists()
→ _acquire_lock("wallet:{user}", ttl=10)   # Redis SET NX PX + 唯一 token
→ 读钱包 → _apply_balance_change()          # 乐观锁 version，冲突重试≤3
→ _record_transaction()                     # WAL 流水（同事务，不可篡改）
→ _release_lock()                           # Lua 校验 token 才删除（防误删）
```
- 关键点：分布式锁 + 乐观锁双保险；余额变更与流水同事务 = 账实一致。

## 三、数字速查（紧张时最易卡壳的，背下来）

### 端口
| 服务 | 端口 | 服务 | 端口 |
|---|---|---|---|
| nginx 入口 | 10090 | gateway 实例 | 10092/10089/10093/10094 |
| 容器内 app | 10086 | Prometheus | 9090 |
| Grafana | 3101(:3000) | Loki | 3102 |
| postgres/redis | 5432/6379（不对外） | | |

### 性能与容量
- 单实例：/health **356 QPS**（并发50）/ 312（并发100）；业务接口 250-280 QPS
- 整系统：**800 并发近零错误**（Locust 实测，4 实例 × 200）
- 连接池：asyncpg min=20 max=50/实例；Redis 无密码内网

### 限流与伸缩
- 用户限流：QPS 2000 / 并发 200 / 日 50 万；admin 更宽
- Nginx：auth burst=100 nodelay；全局 burst=1000；WAF 500r/s + 100 conn/IP
- autoscale：**高>40 QPS / 低<12**，min=1 max=4，interval=30s，cooldown=60s
- nginx 故障转移：connect_timeout 2s，next_upstream_tries 4

### SLO（达成即健康）
- 错误率 < 1%；p95 < 5s；首 token p95 < 3s；日成本 < 50 元；缓存命中 > 30%

### 支付
- 计费：10 元/万 token；渠道成功率 95%；模拟延迟 1-3s；新用户 0 元
- 锁：TTL 10s；乐观锁重试 ≤3 次
- **三个已修并发 bug**（commit 249c52c）：
  1. 锁释放无持有者校验 → Lua 条件删除
  2. 余额更新无重试 → `_apply_balance_change` 重试 3 次
  3. 扣费未检查版本冲突 → 加钱包级锁 + 冲突结果检查

### 数据
- 表：核心 7 张（users/requests/user_usage/conversation_memories/user_profiles/knowledge_chunks/semantic_cache）+ 支付 6 张（wallets/orders/transactions/channels/invoices/reconciliation）
- 扩展：pgvector(768d)、pg_trgm；迁移基线 `76a1f09d2ac8`
- 保留期：conversation 90d / requests 30d / 流水 365d / 缓存 30d
