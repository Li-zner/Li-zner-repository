# 编码与安全规范（分层 / 密钥 / 数据库）

## 1. 分层模型（不可逾越）

```
接入层 → 网关层 → 业务层 → 数据层 → 可观测
```

| 层 | 职责 | 禁止 |
|---|---|---|
| 接入层 | TLS、静态资源、WAF、负载均衡 | 业务逻辑 |
| 网关层 | 认证、限流、熔断、幂等键、脱敏 | 业务规则 |
| 业务层 | 事务、锁、领域规则、状态机 | 直连密钥 |
| 数据层 | SQL、迁移、索引、连接池 | 业务逻辑 |

依赖方向：外层可依赖内层，内层禁止依赖外层。

## 2. 目录与命名

```
app/  main.py(入口)  core/  middleware/  routes/(只做校验组装)
      services/(事务锁状态机)  models/
scripts/  tests/  alembic/  docs/  _env.py  docker-compose.yml
```

- 命名：文件/变量 `snake_case`；类 `PascalCase`；常量/环境变量 `UPPER_SNAKE`（统一前缀）。
- 路由：`/api/v1/<资源>`（复数）；错误码：`模块_错误` 全大写。
- 类型标注必须有（Python：参数与返回值）；函数单一职责。
- 配置读取统一走 `_env.py`/`config.py`，禁止散落 `os.getenv`。
- 文件头一句话用途；docstring 写「做什么/入参/返回」；锁、事务、幂等、边界必须注释「为什么」。

## 3. 密钥体系（唯一权威源）

```
权威源: /etc/<project>/.env   （root:root 644；不要用 600——普通用户读取会 PermissionError）
读取:   _env.py（进程环境变量 → 根 .env 占位 → 安全目录，先读到的优先）
注入:   docker-compose env_file 用 UNC（Windows）/ POSIX（Linux）路径
```

**红线（禁止清单）**：
- 密钥写进代码、compose、配置文件、README；`.env`/凭据进 git（含历史）
- 日志打印密码/Token/API Key/手机号/身份证号
- 给默认值兜底后仍可启动（如 JWT_SECRET 缺失必须启动失败 = fail loudly）
- 数据库错误信息直接透出（DSN/密码/内部路径脱敏）

**轮换流程**：改安全目录 `.env` → 重建容器 → 全链路探活（入口→登录→核心业务→付费）。

## 4. 注入与安全防护

- 上传：扩展名白名单 + MIME + 内容特征检测；大小限制。
- LLM/Agent：用户输入与上传内容进上下文前必须清洗（防提示词注入）。
- SQL：一律参数化，禁止字符串拼接；CORS 白名单，不放开 `*`；登录接口严格限流防撞库。
- 上线前自查：grep 无明文密钥、日志无敏感明文、限流/熔断已配、WAF/安全头就位。

## 5. 数据库

- 表名/字段 `snake_case`；主键 `id BIGSERIAL`（多实例/合并用 UUID）；必备 `created_at`/`updated_at`
  （`TIMESTAMPTZ`，UTC 存储，展示层转本地）。
- 资金/并发敏感表加 `version`（乐观锁）；审计/流水表只追加，禁止 UPDATE/DELETE。
- 迁移：每张表/每个变更一个迁移文件，走 `alembic revision`；**禁止手工 ALTER**。
  陷阱：`CREATE TABLE IF NOT EXISTS` 不给旧表补列（加列用 `ADD COLUMN IF NOT EXISTS`）；
  `alembic.ini` 必须 ASCII（GBK 读中文注释会炸）；密码含 `%` 时 configparser 插值炸
  （不写 ini，直接传 URL）。
- 事务：写操作在 service 层显式事务（`async with conn.transaction()`）；
  **锁、余额变更、流水必须在同一事务**（杜绝账实不符）；并发扣款 = 分布式锁 + 乐观锁双保险；
  幂等 = 唯一索引 + 幂等键。
- 生命周期：会话/日志/缓存/流水设保留期，清理先 `--dry-run`；备份定时 `pg_dump` 保留多份，
  每月恢复演练。
- 连接池：asyncpg min/max 启动配置，`init_pool` 失败 **fail-fast**（不静默降级）；
  连接串统一 `_env.db_url(host)`（宿主机 `localhost`，容器内服务名）。
