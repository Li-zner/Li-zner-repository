# 长链任务执行协议

> 定义 AI 在「多轮、多步骤」任务中的行为方式。核心：**计划 → 执行 → 自测 → 报告**。

## 1. 计划（每个任务开始前）

- 把任务拆成可勾选的小项，用 TODO 清单跟踪。
- 每个 TODO 写清楚：做什么 + 验收怎么判断。
- 一次只做一个 TODO，做完勾掉再下一个（不批量报完成）。

## 2. 执行纪律

- 改动文件前先读当前内容。
- 复用模板/参考，不重复造轮子。
- 涉及多文件 → 优先批量编辑工具，保持原子性。
- 密钥、端口、协议一律以 `04-待人类填写/` 为准。
- 卡住时先自查（读文档、查日志、跑测试），再问人。

## 3. 自测（每步必须）

| 改动类型 | 最小自测 |
|---|---|
| Python 代码 | `ast.parse` 语法检查 / 跑单元测试 |
| 接口 | curl/httpx 冒烟（含错误分支） |
| 数据库 | `alembic upgrade head` + 回滚验证 |
| 脚本 | `bash -n` 语法检查 |
| compose | `docker compose config` 校验 |
| 部署 | 全链路探活（入口→登录→核心业务） |

## 4. 遇到需要人类决策的信号（停下问）

- `[待定]` 未填
- 协议/字段矛盾
- 凭据缺失
- 验收标准无法满足且原因不明
- 需要新增表/接口但不在 MVP 范围

## 5. 报告

- 每阶段 + 最终各一份报告，格式见 `04-交付报告模板.md`。
- 报告含自测证据（命令 + 结果摘要）。
- 未验收的绝不写「完成」。
