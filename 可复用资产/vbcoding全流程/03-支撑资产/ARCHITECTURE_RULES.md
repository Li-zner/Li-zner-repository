# 架构规则（ARCHITECTURE_RULES）

> **用途**：架构与协议阶段注入给 AI 的强制约束——让 AI 从第一行代码就规避事务、并发、重复造轮子问题。
> **何时用**：写骨架前注入（见 `../02-任务-prompt/编码-prompt.md`）；审阅时对照本文件核验。
> **来源**：vbcoding.txt「4 层审查模型 → 架构与协议阶段」，通用化。

## 1. 事务边界（数据库设计必须优先考虑）

1. **任何「插入/更新 + 外部调用（发 Token / 发短信 / 发邮件 / 调第三方）」必须封装在数据库事务中**：
   - 先落库状态，再做外部调用；外部失败回滚状态
   - 禁止：先发外部调用、后写库（外部已生效但库无记录 → 账实不符）
2. **编码前先明确指出本项目并发竞争点**（扣减库存 / 余额变动 / 抢锁 / 签到计数 / 幂等建单），逐点声明对策：
   - 资金/库存类：数据库乐观锁（Version 字段）+ Redis 分布式锁**双保险**
   - 幂等操作：唯一索引 + 幂等键，占位先行
3. **读多写少 / 有重复问法**：接入语义缓存（可复用资产 `../../MCP sever/语义缓存/`）

## 2. 成熟库优先（禁止重复造轮子）

4. 凡是业界有成熟库的能力，**禁止手写底层实现**：

   | 能力 | 首选 |
   |---|---|
   | 限流 | fastapi-limiter / 可复用资产 `../../MCP sever/分布式锁与限流/` |
   | JWT | python-jose / 可复用资产 `../../MCP sever/JWT令牌签发与校验/` |
   | 健康检查 | 框架内置 / 社区标准库 |
   | ORM / 迁移 | SQLAlchemy + Alembic |
   | 密码哈希 | passlib bcrypt（禁止自写哈希算法） |
   | Lint / 格式化（Python） | ruff（毫秒级，lint+format 一体；CI 门禁首选） |
   | 静态安全扫描 | semgrep（模式匹配找 bug 变体；审阅 L3 的机器化） |

5. **选库原则**：维护活跃、文档全、社区大；不引「单人维护小库」；不重复引入功能重叠的库
6. **保持代码精干**：能用 50 行标准库解决，不写 200 行自研；新增依赖需有理由

## 3. 注入方式（怎么用）

- 复制本文件内容，粘贴进 `../02-任务-prompt/编码-prompt.md` 的「第二步投喂资产」或「第三步写骨架」指令
- 或作为独立文件，要求 AI 写骨架前必读
- 审阅阶段对照本文件核验：事务 / 并发 / 选库是否合规（对应审阅 L2/L4）

## 4. 交付检查

- [ ] 每个涉及「写库 + 外部调用」的路径都声明了事务边界
- [ ] 并发竞争点已列出，且锁/幂等对策明确
- [ ] 新引入能力全部对照「成熟库优先」表，无自研重复造轮子
- [ ] Python 项目 CI 至少过 ruff（行业门禁，与项目自检 check_code_rules.py 并存，缺一不可）
