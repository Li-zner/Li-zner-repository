# AI Agent 开发全流程

> **骨架**：开源 [mattpocock/skills](https://github.com/mattpocock/skills)（22 万 star，反 vibe coding 的工程纪律：Grill / 共享词汇 / TDD / 架构治理）。
> **血肉**：本机 `可复用资产/` 全部积累——harness 规则、5 个 MCP Server、6 个技能、验收工具。
> **核心主张**：AI 写代码时代，工程基本功（需求对齐 / 反馈环 / 架构收敛）比以往更重要；约束要「流程引导 + 硬门禁」双层，而不是只靠一条强提示词。

## 何时使用

- 从零开发一个新的 AI Agent / AI 应用（接入 LLM、工具、存储）
- 给现有 Agent 增加能力（新工具、新 MCP、新场景）
- 评估一个已有 Agent 的工程化程度（按七阶段逐项打分）
- 面试 / 演示前快速判断「这套流程还差哪一环」

**铁律**（贯穿全程，违反即该阶段重做）：
- 需求没对齐、验收标准推导不出 → 阶段 1 不结束，禁止进入 2
- 每步先自测再进入下一步；写完当场跑写后检查（债不过夜）
- 密钥一律走安全目录，禁止硬编码；`.env` 不进 git
- 遇到 `[待定]` / 矛盾 / 凭据缺失 → **停下询问，禁止猜测**

## 阶段 1：需求拷问（Grill，写代码前必做）

**目的**：让 Agent 在动手前把需求、边界、异常、验收标准全部问清楚——这是 Matt 对抗「需求错位」的第一道闸，也是本机工作规则「遇到 [待定] 停下询问」的流程化。

**拷贝即用的问题清单**（让 Agent 逐条问，不得跳过）：

1. **目标**：一句话说清要交付什么、给谁用、解决什么痛点？
2. **场景**：核心使用路径是什么？用户从进入到最后拿到结果走几步？
3. **边界**：哪些明确不做？（范围外写进 MVP 范围）
4. **异常**：输入非法 / 依赖不可用 / LLM 返回异常时分别怎么表现？
5. **验收**：怎么算「做完」？可量化的通过标准是什么（自测命令 / 指标）？
6. **凭据**：需要哪些密钥 / 外部依赖？现在有吗？缺失必须明说，禁止猜默认值
7. **并发与安全**：会同时多少人用？哪些数据敏感？（参考 `../../harness/01-规则/01-编码与安全规范.md`）

**产出物**（直接落到 `../../harness/04-待人类填写/` 模板，只读区不改模板本身）：
- `01-项目协议.md`：技术栈、目录、分层约定
- `02-业务定义.md`：领域术语、规则、状态机
- `03-MVP范围与验收.md`：功能范围 + 验收标准
- `04-外部依赖与凭据.md`：依赖清单 + 密钥项（值存安全目录）

**出口条件**：四份模板填完且无 `[待定]` 残留，验收标准可推导 → 才进入阶段 2。

## 阶段 2：词汇表 + 领域建模

**目的**：建立 Agent 与你的「共享词汇」，消除啰嗦输出（Matt 的 token 成本优化，也防跑偏）。

1. 从阶段 1 的 `02-业务定义.md` 提取领域术语，建 `CONTEXT.md`（项目根）：
   - 每个术语一句话定义 + 反例（模型容易混淆的边界）
   - 例：`materialization cascade` 四字词代替二十字描述
2. 建模要点：
   - 实体、关系、状态机（参考 `../../harness/03-参考-项目经验/02-机制库参考.md`）
   - 权限 / 租户 / 审计这类横切关注点提前画进模型，不要事后补
3. 复杂度判断：领域复杂 → 先写 `docs/领域模型.md`；简单 → CONTEXT.md 内一句带过

**出口条件**：CONTEXT.md 覆盖阶段 1 全部术语，无歧义。

---

## 阶段 3：架构决策（ADR）

**目的**：把不可逆的技术决策在写代码前拍板，并留档（避免「先跑通再重构」）。

**必拍板项**（对照 `../../harness/01-规则/01-编码与安全规范.md` 分层模型与密钥体系）：
- [ ] **分层**：接入 / 网关 / 业务 / 数据四层职责与依赖方向
- [ ] **密钥**：权威源、读取链路（`_env.py`）、fail loudly 项（缺密钥必须启动失败）
- [ ] **数据库**：表设计是否走迁移（Alembic）；资金/并发敏感表加 version 乐观锁
- [ ] **并发**：锁、限流、幂等策略（复用 `../../MCP sever/分布式锁与限流/`）
- [ ] **可观测**：日志 / 指标 / 追踪接入点
- [ ] **AI 专项**：模型选择、缓存（`../../MCP sever/语义缓存/`）、检索（`知识库双通道检索/`）、纠错（`模型归因纠错映射/`）

**产出物**：`docs/ADR-<主题>.md`，格式：背景 → 候选方案 → 决策 → 理由 → 后果（含回滚路径）。

**出口条件**：上表全勾、ADR 落档。

## 阶段 4：TDD 实施

**目的**：小切片、每步自测、红绿重构——Matt 的反馈环，也是本机「每步先自测再进入下一步」的固化。

1. **纵向切片**：按「一条用户路径 = 一个切片」，不要按技术层切（先竖切后横切）
2. **每切片循环**：
   - 先写失败测试（红）→ 实现到过（绿）→ 重构收敛
   - 每步 `python -m py_compile` + 跑对应单测，通过才进下一步
3. **硬门禁**：`../../harness/02-模板/项目骨架/scripts/check_code_rules.py`（纯 AST 零依赖）接入 CI：
   - 函数 ≤80 行 / 文件 ≤600 行，违规发布失败（四道防线之「机器门禁」）
   - 禁止 `|| true` 跳过门禁
4. **新增代码纪律**：本次新增的函数/文件必须合规；既有历史债记豁免名单（写理由 + 到期复审），不许过夜

**出口条件**：每个切片有可运行检查；门禁通过。

---

## 阶段 5：五阶段验收

**目的**：用真实基础设施跑通「认证 → 并发限流 → 语义缓存 → 知识检索 → 纠错映射」五件套。

- 调用 `../../AI应用验收工具/SKILL.md`（一键 `python verify_all.py`）
- 无 Redis / PostgreSQL / 密钥的环境：对应阶段 SKIP 并说明原因，**不假装通过**
- 验收数据用 `__accept__` 前缀，验收后清理，不留残留

**出口条件**：无 SKIP 时全通过；有 SKIP 时列出原因与恢复条件。

---

## 阶段 6：写后检查 + 交付

按 `../../harness/05-执行流程/` 收尾：

1. **三检查点**（`../../harness/01-规则/02-防熵机制.md`）：
   - 结构合规：本次新增函数 ≤80 行 / 文件 ≤600 行，违规当场重构
   - 逻辑质量：分支/边界/空值/异常全覆盖？并发无竞态？资源释放？信任边界有校验？
   - 可读性：6 个月后别人改这段代码能否快速看懂？
2. **验收清单**：`03-验收清单.md` 逐项对照，不过不得宣称「完成」
3. **交付报告**：`04-交付报告模板.md`——完成项 / 差异项 / 风险项 / 待人工确认项 / 自测证据（诚实，不报喜不报忧）

---

## 阶段 7：架构收敛（定期，非每次必做）

**目的**：Matt 的 improve-codebase-architecture——定期扫描设计压力点，防泥球。

- 每完成 5 个功能或每 2 周安排 1 小时收敛：
  - 查重复（≥3 处抽公共函数）、超行函数/文件、散落密钥、文档过期
  - 检查门禁是否被绕过（`|| true` 等）
- 发现历史债：记豁免名单（理由 + 到期复审），专项重构时处理，**债不过夜**

## Agent 标准件清单（本机 MCP Server，开发 Agent 时按需接入）

Agent = 编排逻辑（Host）+ 原子能力（MCP Server）。开发新 Agent 时，先看下表能白捡哪些能力：

| MCP Server（`../../MCP sever/` 相对路径） | 能力 | 何时接入 | 依赖 |
|---|---|---|---|
| `JWT令牌签发与校验/` | HS256 签发/校验/刷新轮换 + jti 吊销黑名单 | 任何需要登录态 / 接口鉴权的 Agent | 纯标准库，redis 可选 |
| `分布式锁与限流/` | Redis 分布式锁（Lua 原子释放）+ 三种限流 | 并发扣费 / 抢资源 / 防撞库 | redis |
| `语义缓存/` | L0 LRU → L1 哈希 → L2 pg_trgm 三级缓存 | LLM 调用有重复问法、要省成本降延迟 | redis + PostgreSQL |
| `知识库双通道检索/` | pg_trgm 关键词 + 向量双通道召回 | RAG 场景（法律 / 业务知识问答） | PostgreSQL |
| `模型归因纠错映射/` | 关键词 → 权威答案/引导，LLM 前拦截 | 高风险问题要先拦截 / 要回答确定性 | 零依赖 |

**接入纪律**（源自 `mcp-server开发五步法`）：Tool 原子、知识下沉 Server、编排留 Host；docstring 写清「做什么/何时用/参数含义」；错误返回 `{"error": ...}` 不抛异常。

## 约束强度说明（为什么这套能比裸 prompt 更强）

| 层 | 机制 | 强度 | 何时用 |
|---|---|---|---|
| 提示词级 | 本技能七阶段流程 + 现有 6 个技能 + CLAUDE.md 规则 | 强引导，可被跳过 | 日常开发（阶段 1-7） |
| 硬门禁 | `check_code_rules.py` + CI 强制，违规发布失败 | 不可跳过 | 提测 / 上线前（阶段 4/6 收尾） |

开源 mattpocock/skills 只有提示词级；你的优势是**两层都有**。记住：流程约束再强也可能被绕过，硬门禁才是底线；两条腿走路，缺一不可。
