# 启动流程（新 AI 接项目时的第一步）

> 人类已完成 `04-待人类填写/` 后，把 harness 路径交给 AI，AI 按本流程执行。

## Step 0 — 阅读（先读再动）

1. `00-主人意图与使用方法.md`（主人的意图与期望——**必读第一份**）
2. `00-README.md`
3. `01-规则/00-工作规则.md`
4. `04-待人类填写/`（全部，逐字读）
5. `05-执行流程/01-启动流程.md`（本文件）

读完后，**向人类复述**：项目名、核心定位、端口表、MVP 阶段、验收标准。
确认无误再开工（这是防跑偏的第一道闸）。

## Step 1 — 建项目骨架

1. 复制 `02-模板/项目骨架/` 到项目根目录。
2. 按 `04-待人类填写/01-项目协议.md` 修改：服务名、端口、环境变量前缀。
3. 初始化 git（`.gitignore`/`.gitattributes` 已含）。
4. 确保 `_env.py` 能读到安全目录（先让 `get("JWT_SECRET")` 返回非空）。

## Step 2 — 阶段 0（骨架）

- [ ] compose 能起 app + postgres + redis
- [ ] `/health` 200
- [ ] 密钥体系验证通过
- 报告阶段 0 完成

## Step 3 — 按阶段推进

对每个阶段（`04-待人类填写/03-MVP范围与验收.md`）：
1. 列 TODO 清单
2. 实现（复用 `03-参考-项目经验/` 的机制与片段）
3. 自测（语法 + 接口 + 迁移）
4. 对照该阶段验收标准
5. 输出阶段报告（`05-执行流程/04-交付报告模板.md`）

## Step 4 — 全部阶段完成后

- [ ] 跑 `05-执行流程/03-验收清单.md` 全量
- [ ] 输出最终交付报告
- [ ] 把新踩的坑追加到 `03-参考-项目经验/03-踩坑清单.md`
- 交给人类审核

## 禁止

- 跳过阅读直接写代码
- 遇到 `[待定]` 自行决定
- 一次吃下超过一个阶段（先确认再继续）
