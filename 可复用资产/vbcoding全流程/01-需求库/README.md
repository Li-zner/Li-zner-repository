# 01-需求库

> **用途**：每个新项目的「源头」——把项目需求、背景、架构图谱、协议、验收标准全部写在这里，
> 后续所有阶段（编码、审阅、测试）都以本库为唯一依据。

## 为什么必须写进需求库（而不是口头/临时文件）

- AI 的所有决策（架构、代码、测试）都从需求推导；需求不清，AI 只能猜
- 审阅代码时对照「验收标准」逐项核验，没有需求库就无法判断「对不对」
- 项目隔几个月再看，需求库是唯一能还原当初「为什么这样做」的文档

## 每个新项目怎么做

1. 在 `01-需求库/` 下新建一个文件，命名 `项目名-需求.md`（如 `简历RAG-需求.md`）
2. 复制 `模板-01-项目需求与背景.md` 的内容填进去：
   - **项目背景**：为什么做、给谁用、解决什么痛点（一段话说清）
   - **需求拆解**：核心使用路径、功能清单（可勾选）、边界（明确不做）
   - **架构图谱**：文字版分层/模块/数据流/依赖（先画文字图，后续可配图）
   - **协议**：接口协议、数据协议、鉴权协议、错误码（协议先行）
3. 复制 `模板-02-验收标准与MVP.md` 填进去：
   - **MVP 范围**：必须做 / 不做 / 可延后
   - **验收标准**：每项需求的可量化通过标准（自测命令、指标、行为断言）
   - **完成定义**：Definition of Done（代码 + 测试 + 审阅 + 文档全过才叫完成）
4. 定稿前过「澄清环节」（`模板-01` 第 6 节）：让 AI 以实现者身份通读全部定稿内容，
   系统性挑出模糊/矛盾/缺失点，逐个问答并记录；全部澄清（或转为有归属的遗留项）后才算定稿
   （借鉴 GitHub spec-kit 的 clarify：主动挑刺，不等编码时踩雷）

## 本目录约定

- 一个项目一个文件（或一个子目录），文件名清晰，不覆盖他人项目
- 模板文件（`模板-*.md`）只读，不要改；复制后填新内容
- 填到 `[待定]` 的项：**停下问人，禁止 AI 猜测**（这是全流程第一铁律）

## 文件清单

| 文件 | 内容 | 何时填 |
|---|---|---|
| `README.md` | 本说明 | - |
| `模板-01-项目需求与背景.md` | 背景 / 拆解 / 架构图谱 / 协议 / 澄清记录 | 项目启动时 |
| `模板-02-验收标准与MVP.md` | MVP / 验收标准 / 完成定义 | 项目启动时（编码前定稿） |
