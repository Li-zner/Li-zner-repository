# 学习计划：Python 手写编程训练（两周版）

> 目标：补上"读得懂但写不出"的短板，达到 8-11K AI 应用岗面试能现场手写的水平。
> 方法：每天 30-60 分钟，**先手写、再对比、再提交 git**。题目全部从自己的项目里抽——只有写自己熟悉的东西才有动力，写完还能反哺对项目的理解。
> 规则：① 先不看答案硬写 ② 写完必须 `git commit` ③ 卡住 15 分钟才允许看答案 ④ 每题写完用一句话说清"这题在项目里对应哪里"。

---

## 第 1 天：装饰器（对应 `auth.py` 的依赖思想）

- [ ] 手写一个装饰器：给任意函数加日志（打印函数名 + 参数 + 耗时）
- [ ] 进阶：支持带参数的装饰器（如 `@retry(times=3)`）
- [ ] 说清：装饰器本质是什么（`func = decorator(func)`）
- [ ] 项目对应：FastAPI 的 `Depends(get_current_user)`、`@router.post` 都是装饰器思想
- [ ] `git commit -m "训练D1: 装饰器"`

## 第 2 天：Redis 计数器限流（对应 `rate_limit.py`）

- [ ] 手写 `check_qps(username)`：`INCR` 一个 key，首次设 2 秒过期，返回是否超限
- [ ] 手写"并发计数"：`INCR` 后超限要 `DECR` 还回去
- [ ] 说清：为什么限流计数必须放 Redis 而不是内存
- [ ] 项目对应：`app/middleware/rate_limit.py`
- [ ] `git commit -m "训练D2: 限流计数"`

## 第 3 天：asyncio 并行（对应多 Agent 骨架）

- [ ] 手写两个 `async def` 函数（模拟 LLM 调用，`await asyncio.sleep(2)`）
- [ ] 用 `asyncio.gather` 并行跑，测量总耗时（应≈2s 而非 4s）
- [ ] 手写信号量：限制同时最多 2 个并发
- [ ] 说清：`await` 时事件循环在干什么
- [ ] 项目对应：`app/agents/orchestrator.py` 的 `asyncio.gather`
- [ ] `git commit -m "训练D3: asyncio并行"`

## 第 4 天：乐观锁 UPDATE（对应支付核心）

- [ ] 手写 `update_balance(conn, user_id, delta, version)`：
      `UPDATE wallets SET balance=balance+$1, version=version+1 WHERE user_id=$2 AND version=$3`
- [ ] 手写"冲突重试循环"（最多 3 次：重读 → 再试）
- [ ] 说清：为什么 `WHERE version=$3` 影响 0 行 = 冲突
- [ ] 项目对应：`app/payment/service.py` 的 `_do_update_balance` / `_apply_balance_change`
- [ ] `git commit -m "训练D4: 乐观锁"`

## 第 5 天：LRU 缓存（对应语义缓存 L0）

- [ ] 手写 `OrderedDict` 版 LRU：get 移到尾部、set 超容量淘汰最旧
- [ ] 进阶：不用 OrderedDict，用 dict + 双向链表（可选）
- [ ] 说清：为什么 LRU 是 O(1)
- [ ] 项目对应：`app/core/semantic_cache.py` 的 `_LRUCache`
- [ ] `git commit -m "训练D5: LRU"`

## 第 6 天：FastAPI 最小接口（对应 `main.py`）

- [ ] 手写一个最小 FastAPI 应用：`GET /health` 返回 JSON
- [ ] 手写一个 `POST /echo` 接收 JSON 返回
- [ ] 加一个依赖注入函数（`Depends`）做简易鉴权
- [ ] 用 uvicorn 跑起来，`curl` 验证
- [ ] 说清：FastAPI 为什么靠类型注解生成文档/校验
- [ ] `git commit -m "训练D6: FastAPI"`

## 第 7 天：JWT 签发与校验（对应 `auth.py`）

- [ ] 手写 `create_token(payload, secret)`：python-jose 编码 + exp
- [ ] 手写 `verify_token(token, secret)`：解码 + 捕获 JWTError
- [ ] 手写一个函数验证"改一个字符签名就失败"
- [ ] 说清：HS256 为什么能防伪造
- [ ] 项目对应：`app/middleware/auth.py`
- [ ] `git commit -m "训练D7: JWT"`

## 第 8 天：生成器与上下文管理器

- [ ] 手写一个生成器：逐行读大文件（`yield`）
- [ ] 手写一个上下文管理器（`__enter__`/`__exit__`）模拟开关连接
- [ ] 说清：生成器为什么省内存；`with` 为什么保证清理
- [ ] 项目对应：SSE 流式（`yield`）、`async with pool.acquire()`
- [ ] `git commit -m "训练D8: 生成器/上下文"`

## 第 9 天：SQL 查询（asyncpg）

- [ ] 手写：建连接、`fetchrow`、`fetch`、`execute`

- [ ] 说清：为什么用参数占位而不是字符串拼接
- [ ] 项目对应：`app/core/db.py`、`app/payment/service.py`
- [ ] `git commit -m "训练D9: asyncpg"`
