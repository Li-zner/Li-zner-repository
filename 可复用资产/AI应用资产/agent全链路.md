# Agent 构建全链路（AI 应用工程师落地指南）

> **用途**：从需求到上线的 agent 开发完整链路——每步给"做什么、怎么选、坑在哪"，
> 并指向本库可复用资产与官方技能，避免每次从零摸索。
> **何时用**：启动任何 agent/AI 应用项目时通读一遍；开发中按环节回查。
> **关系**：工程纪律与阶段流程看 `../skill/AI Agent 开发全流程/SKILL.md`（不重复）；
> 项目选型看 `选型清单.md`；RAG 细节看 `RAG构建.md`；**安全审计看 `安全审计.md`（首要考虑，先于本文）**。

## 0. 全链路总览

```
需求定义 → 架构模式选型 → 模型与提示层 → 工具层(MCP) → 记忆层
   → 编排实现 → 护栏与安全 → 评测集 → 部署 → 可观测 → 迭代
```

**铁律**：评测集在写第一行代码之前就要开始收集（真实用户问句）；
没有评测的 agent 迭代 = 盲人骑车。
**铁律二（安全）**：威胁模型在需求评审时就要建（见 `安全审计.md`）——
功能 bug 损失功能，安全缺口损失产品。

## 0.5 设计原则（十二条军规，安全置顶）

来源：humanlayer/12-factor-agents（2.6 万星，整包见 `skills/12-factor-agents/`）。
主论点：**生产 agent 大多是确定性代码，只在关键点撒一点 LLM**。原则即军规，冲突时安全 > 可控 > 灵活：

0. **安全先行**：威胁模型先于功能设计（本库新增置顶原则，落地见 `安全审计.md`）；
1. 自然语言到工具调用：LLM 的唯一职责是把用户意图转成结构化 JSON；
2. Own your prompts：提示词自己写、版本化，绝不继承框架的黑盒模板；
3. Own your context window：上下文里放什么自己说了算（本库三层按需读取即此思想）；
4. 工具只是结构化输出：模型填 JSON、普通代码执行——工具测试退化为单测；
5. 执行状态与业务状态统一：单一事实源，别让 agent 私藏第二份状态；
6. 启动/暂停/恢复用简单 API：长任务三件套的理论出处；
7. 用工具触达人类：人工确认做成 `ask_human` 工具，人机边界能力化；
8. Own your control flow：循环写在你的代码里，不由框架定义；
9. 错误折叠进上下文：把报错精简后喂回模型自纠（instructor 的验证重试同理）；
10. 小而专的 agent：宁要多个窄 agent 组合，不要全能巨兽；
11. 从任何地方触发：Slack/邮件/webhook/cron 都是入口；
12. agent 是无状态 reducer：`f(事件历史, 新事件) -> 状态`——agent_gateway cdc/worker 的理论名。

## 1. 需求定义（最重要的 20%）

- 用一句话说清：**输入是什么、输出是什么、判定对错的标准是什么**；
- 把"不确定性"分级：可枚举（走工作流/状态机）、半开放（走 agent + 工具）、纯生成（走提示工程）——
  **能不用 agent 就不用**，工作流更便宜更可控；
- 验收标准可断言（对接 `../vbcoding全流程/01-需求库/模板-02-验收标准与MVP.md`）：
  例"20 条评测集上答案相关性 >= 0.8，工具调用错误率 < 5%"。

## 2. 架构模式选型（按不确定性升级）

| 模式 | 适用 | 成本 | 参考 |
|---|---|---|---|
| 单次调用 + 提示 | 分类/抽取/改写 | 最低 | claude-api 技能 `shared/tool-use-concepts.md` |
| 工作流（固定步骤） | 流程确定的业务 | 低 | LangGraph 链式图 / Dify |
| 单 agent + 工具 | 开放任务但领域窄 | 中 | pydantic-ai / openai-agents |
| 多 agent 协作 | 角色分工/互相校验 | 高 | CrewAI / AutoGen / LangGraph 多节点 |
| RAG 增强 | 需要私有知识 | 中 | 见 `RAG构建.md`，可与以上任意组合 |

**坑**：多 agent 不是银弹——每加一个 agent，调试与评测成本翻倍。
先用单 agent + 好工具跑通，有实测瓶颈再拆分。

## 3. 模型与提示层

- 网关：多模型统一接口用 litellm；自建网关参考 agent_gateway（本库 `MCP sever/` 的来源项目）；
- 提示词管理：提示词当**版本化资产**（进 git、有变更记录），不要散在代码字符串里；
- 成本：`claude-api` 技能 `shared/cost-optimization.md` + `shared/prompt-caching.md`（缓存可省 50%+）；
- 结构化输出：一律用 Pydantic 模型约束（pydantic-ai / instructor 思想），
  对接本库红线"输入防御：Pydantic + max_length"。

## 4. 工具层（MCP 化）

- 工具定义三原则：名称动词化、描述写清"何时该用/何时不用"、参数带类型与校验；
- 每个工具独立可测（不依赖 agent 就能单测）；外部依赖加超时与熔断（`../可复用代码/`）；
- 把工具沉淀为 MCP Server 的流程看 `../skill/mcp-server开发五步法/SKILL.md`，
  官方最佳实践与评测工具看 `skills/mcp-builder/`——写完用它的 evaluation 框架自测。

## 5. 记忆层（按需升级，不过度设计）

| 层级 | 用什么 | 什么时候 |
|---|---|---|
| 会话内 | 滑动窗口 + 超限摘要 | 一切对话应用的起点 |
| 跨会话个性化 | mem0 或自建"抽取-合并"记忆 | 用户回来要记得上次 |
| 长期知识 | RAG（见 `RAG构建.md`） | 知识来自文档而非对话 |

**坑**：记忆写入要有合并/去重策略，否则记忆库变成垃圾场（mem0 的解决思路值得抄）。

## 6. 护栏与安全（AI 应用与普通后端的分界线）

**本节是入口不是全部：完整威胁模型与分层检查单见 `安全审计.md`（首要考虑项）。**
以下为编码时的快速红线：

- **输入侧**：提示词注入防护——用户输入先清洗再进上下文（本库红线）；
  工具调用结果同样不可信（间接注入）；
- **输出侧**：敏感信息脱敏、结构化输出校验失败要有兜底重试；
- **资金与配额**：token 预算守卫（`../可复用代码/Token预算守卫.py`）+ 限流（角色分级参考 agent_gateway rate_limit）；
- **人机边界**：删数据、付款、发外网等高危工具必须人确认（对接本库底层规则第 13 条；
  12-factor 第 7 条：把确认做成 ask_human 工具）；
- **可观测埋点从第一天就要**：见第 9 节。

## 7. 评测集建设（先于编码）

- 从真实场景收集 20-50 条输入 + 期望行为（黄金集）；
- 三类指标：任务成功率（规则可判定的比例）、LLM 评分（rubric 打分）、人工抽检（每周）；
- RAG 场景用 ragas 三件套：忠实度（faithfulness）、答案相关性、上下文精度；
- 评测集进 git、随 bug 修复扩充——**每个线上 bug 都变成一条新评测用例**；
- agent 改提示词/换模型后必须跑全量评测再发布（对接 vbcoding 的收敛循环：评测不收敛不上线）。

## 8. 部署形态

| 形态 | 适用 | 参考 |
|---|---|---|
| FastAPI 服务 + 队列 | 大多数后端 agent | agent_gateway 结构（限流/熔断/审计已内建） |
| 平台托管（Dify 等） | 内部工具、快速验证 | 选型清单第二节 |
| 常驻 worker（CDC/轮询） | 长任务、定时 | agent_gateway cdc/worker 模式（leader 锁 + 断点续传） |

**长任务三件套**（agent_gateway 已验证）：任务表 + 幂等键 + 超时恢复；
**流式输出**：SSE 心跳 + 背压控制（参考 `app/core/stream_utils.py`）。

## 9. 可观测与迭代

- trace 记什么：每次调用的输入/输出/token/耗时/工具调用链/错误——langfuse 自托管一键起；
- 告警看什么：错误率、P95 延迟、token 成本日曲线、评测分漂移；
- 迭代闭环：线上 bad case → 转评测用例 → 修提示词/检索/工具 → 评测全绿 → 发布
  （这与 vbcoding 的收敛循环同构：**AI 应用的"测试没过"就是评测分不达标**）。

## 10. 落地检查单（发布前逐项过）

- [ ] **安全审计完成**：`安全审计.md` 检查单逐项过，对抗用例集全绿，遗留风险人签字
- [ ] 评测集 >= 20 条且全绿；bad case 有回归用例
- [ ] 所有工具：超时 + 熔断 + 幂等（可复用代码三件）
- [ ] 提示词版本化；结构化输出 Pydantic 校验
- [ ] token 预算与限流就位；高危工具人确认
- [ ] trace 可查单次调用全链路；成本日曲线可见
- [ ] 输入注入防护抽查（构造对抗输入跑一遍）
- [ ] 密钥全走 .env；日志无敏感明文
