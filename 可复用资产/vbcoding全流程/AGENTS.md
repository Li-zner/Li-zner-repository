# AGENTS.md — vbcoding 全流程入口（agent 必读）

> 本目录是 AI 辅助开发流程资产。**禁止一次性读完全部文件**，按下面三层路由按需加载。
> 人类视角的总览与设计理念在 `README.md`，agent 无需读取（其中的分级标准等操作性内容，
> 唯一权威源都在本文件）。本文件中的相对路径均以本文件所在目录为基准。

## 三层读取模型

| 层 | 何时读 | 读什么 |
|---|---|---|
| L0 必读 | 每次会话开始，读一次全程有效 | 本文件 + `00-底层规则/底层规则.md` |
| L1 任务入口 | 按当前任务类型，**只读一个** | `02-任务-prompt/` 下对应文件 |
| L2 支撑资产 | 任务入口文件会指明「何时读哪个」，不要提前读 | `03-支撑资产/` 按需 |

## 路由表（当前任务 → L1 入口）

| 当前任务 | 读哪个 L1 入口 |
|---|---|
| 新项目启动 / 需求定稿 / 需求变更 | `01-需求库/README.md` |
| 开发新功能 / 从零搭建 / 加骨架 | `02-任务-prompt/编码-prompt.md` |
| 修 Bug（症状明确，恢复既有行为） | `02-任务-prompt/修复bug-prompt.md` |
| 代码审阅（编码或修复完成后） | `02-任务-prompt/审阅-prompt.md` |

- 任务中途切换类型（如编码中发现要修 Bug）→ 回到本表换读对应入口，不凭记忆继续
- 分不清任务类型或一次来了多件事 → 停下问人，不猜

## 变更分级（先自判，再请示）

接到任务先按下表自判级别（**本表是分级标准唯一权威源**），向人报告「我判为 X 级 + 理由 + 建议」，
人确认后再执行：

| 级 | 判定特征（满足任一即归该级，就高不就低） | 流程 |
|---|---|---|
| S 微改动 | 改文案 / 调参数 / 修一个症状明确的 Bug | 直接改 + 自测 + 汇报；不建需求文件 |
| M 单功能 | 新增或修改一个功能；根因不明或跨函数的复杂 Bug | 需求登记（补进对应项目需求文件）+ 对应任务入口 + 收敛小循环 + 审阅该处 |
| L 新项目/大特性 | 新项目；跨模块特性；**动协议、数据表结构、鉴权** | 全套七阶段 + 澄清环节 + 收敛大循环 + 全量审阅 |

拿不准或依据冲突 → 直接问人，不猜；凡命中 L 的升级触发器（协议/表结构/鉴权）→ 一律自判 L 并提示人。

## 细节下钻（不懂细节读原文）

底层规则与支撑文件都是**精简执行版**；某条规则需要来龙去脉、完整背景或原文条款时，按下表读原文。
读前先确认确实需要，不要预防性全读：

| 想弄清什么 | 读哪份原文 |
|---|---|
| 工作规则总纲（协作约定 / 项目协议 / 密钥体系的来龙去脉） | `../harness/01-规则/00-工作规则.md` |
| 编码与安全完整条款（分层模型 / 迁移陷阱 / SQL 与日志细则） | `../harness/01-规则/01-编码与安全规范.md` |
| 防熵与债务机制原文（豁免名单 / 复审规则） | `../harness/01-规则/02-防熵机制.md` |
| 禁止清单与强制自检清单 | `03-支撑资产/边界约束.md` |
| 架构规则细则（事务边界 / 并发点判别 / 选库表） | `03-支撑资产/ARCHITECTURE_RULES.md` |

两处（精简版与原文）说法不一致 → 取更严格者执行，同时向人报告，把另一处同步修订。

## 全程铁律（详见底层规则，此处为速记）

1. 遇 `[待定]` / 矛盾 / 凭据缺失 → 停下问人，禁止猜测
2. 只做当前任务范围内的事；顺手优化先登记
3. 每步自测再进下一步；无自验证据不宣称完成

## token 预算参考

L0 合计约 2k token；每个 L1 入口约 0.5k~1k token；L2 支撑文件每个 0.3k~0.7k token。
一次编码任务的完整加载（L0+入口+需求+支撑）约 0.8万~1万 token；修 Bug 任务约一半。
