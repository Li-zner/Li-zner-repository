# AI 应用安全审计（首要考虑项）

> **用途**：AI 应用从设计到上线的安全审计链路——威胁模型、分层检查单、审计方法。
> **定位**：本库所有 AI 资产的首要考虑项。功能性 bug 损失的是一个功能；安全缺口损失的是
> 数据、资金、信任乃至整个产品。**先过本文，再谈功能**。
> **何时用**：需求评审时建威胁模型；编码时逐层自查；上线前跑完整检查单；迭代时回归。
> **参照**：OWASP Top 10 for LLM Applications（2025 版）；本库红线（`../vbcoding全流程/03-支撑资产/边界约束.md`）。

## 0. 一条主轴：AI 应用的攻击面 = 传统后端 + 「提示即代码」

传统审计找的是注入代码、越权、配置错误；AI 应用多出一整层：**自然语言就是攻击载荷**。
用户输入、网页内容、检索到的文档、工具返回值——一切进入上下文的文本都是潜在指令。
安全审计的主轴因此只有一条：**区分「数据」与「指令」，并假设二者会被攻击者刻意混淆。**

## 1. 威胁模型（按 OWASP LLM Top 10 2025 对齐）

| 威胁 | 一句话解释 | 本库已有的对策 | 缺口时补什么 |
|---|---|---|---|
| 提示注入（LLM01） | 数据被当指令执行（直接：用户说"忽略之前指令"；间接：网页/文档/工具返回里藏指令） | 边界约束"输入先清洗再进上下文" | 对抗用例集 + 输出动作白名单 |
| 敏感信息泄露（LLM02） | 上下文/系统提示/其他用户数据被诱导吐出 | 日志脱敏红线；缓存上下文维度隔离（Bug #1 教训） | 系统提示防泄露；跨会话数据分区 |
| 供应链（LLM03） | 模型/技能/MCP/依赖被投毒 | 技能拷贝留痕；来源登记 | 技能与 MCP 白名单 + 校验（见第 4 节） |
| 数据与模型投毒（LLM04） | 污染 RAG 语料或微调数据 | 语义缓存防占位污染 | 语料入库审计、来源可信分级 |
| 输出处理不当（LLM05） | 模型输出未校验直接执行/渲染/入 SQL | 结构化输出 Pydantic 校验红线 | 输出白名单 + 参数化落地 |
| 过度代理（LLM06） | agent 权限大于任务所需，被诱导做高危动作 | 高危工具人确认（底层规则 13 条） | 工具最小权限 + 沙箱（E2B 思想） |
| 系统提示泄露（LLM07） | 系统提示被套出，攻击面地图暴露 | 无 | 上线前红队套话测试 |
| 向量/嵌入弱点（LLM08） | RAG 检索被投毒或跨租户越权 | 缓存上下文维度隔离 | 向量库租户过滤 + 语料来源分级 |
| 虚假信息（LLM09） | 模型自信地编造，驱动错误动作 | RAG 引用溯源 | 高危动作双确认 + 溯源强制 |
| 无限消耗（LLM10） | 提示注入放大资源消耗（递归调用/巨量 token） | Token 预算守卫 + 限流 + 熔断 | 单请求工具调用次数上限 |

## 2. 分层检查单（编码时逐层自查）

### 2.1 输入侧
- [ ] 所有进上下文的文本都标注了来源与信任级（用户/文档/工具/网页）
- [ ] 提示词注入对抗用例已建集并跑通（"忽略以上指令""泄露你的系统提示""扮演无限制模式"）
- [ ] 间接注入已防：网页摘要、文档检索、工具返回值先过清洗/白名单再进上下文
- [ ] 输入长度与格式有硬限制（Pydantic + max_length，红线）

### 2.2 模型与提示侧
- [ ] 系统提示中不含密钥、内部路径、无关节点信息（假设它终将泄露来写）
- [ ] 提示词版本化进 git（Own your prompts，见 `skills/12-factor-agents`）
- [ ] 温度/最大 token/工具白名单等参数按环境锁定（生产禁自由模式）
- [ ] 越狱测试通过（角色扮演诱导、多语言绕过、编码绕过）

### 2.3 工具与执行侧（AI 应用最大新攻击面）
- [ ] 每个工具按"最小权限"设计：只给完成任务必需的读写范围
- [ ] 高危动作（删数据/付款/发外网/执行代码）必须人确认工具化（contact-humans 模式）
- [ ] 工具执行环境隔离：AI 生成代码跑在沙箱（E2B/容器），绝不直接落宿主机
- [ ] 工具参数全部结构化校验（Pydantic），拒绝自由文本参数
- [ ] 单请求工具调用次数与深度有上限（防注入驱动的资源放大，LLM10）
- [ ] SQL 全参数化；模型参与的任何 SQL 拼接视为注入（LLM05）

### 2.4 输出侧
- [ ] 模型输出不直接进 HTML/SQL/Shell——先结构化校验再使用
- [ ] 输出脱敏：不回显内部错误堆栈、DSN、其他用户数据
- [ ] 引用溯源：RAG 回答必须可回链来源（LLM09 缓解）
- [ ] 高危输出的双人复核或灰度（首次上线期间）

### 2.5 数据侧
- [ ] 多租户隔离贯穿：缓存（cache_ctx）、向量库（租户过滤）、记忆（按用户分区）
- [ ] RAG 语料来源可信分级；外部爬取内容入库前过审计
- [ ] 日志与 trace 不含敏感明文（红线）；trace 平台本身有访问控制
- [ ] 训练/微调数据如有，来源与授权可追溯（LLM04）

### 2.6 供应链
- [ ] 技能/MCP/依赖白名单制；新引入走"来源登记 + 差异审阅"（本库拷贝件留痕制度）
- [ ] 锁定版本（requirements/lockfile）；升级走变更审阅
- [ ] 模型供应商变更视为安全事件：重新跑对抗用例集
- [ ] .env 密钥轮换方案就位（`../skill/密钥与配置治理/SKILL.md`）

### 2.7 运维侧
- [ ] 预算与限流全开（Token 预算守卫 + 角色限流 + 熔断）
- [ ] 安全事件日志独立通道；agent 的每次工具调用可审计到"谁、何时、参数、结果"
- [ ] 有"一键停用"开关：模型侧（换降级模型）、工具侧（禁用高危工具）
- [ ] 红队回归纳入迭代：每个安全修复转一条对抗用例（与收敛循环同构）

## 3. 审计方法（四步循环）

1. **威胁建模**（需求评审时）：画数据流图，标出每一处「不可信文本进入上下文」与
   「模型输出触达真实世界」的点——这两类点是全部攻击面的入口与出口；
2. **对抗用例集**（编码时）：按第 1 节威胁逐类写 5-10 条对抗输入，进评测集，
   与功能回归同跑（安全用例不过 = P0，走 `../vbcoding全流程/03-支撑资产/收敛循环.md`）；
3. **静态与依赖扫描**（CI 时）：ruff/semgrep 常规扫描 + 依赖漏洞扫描；
   AI 特有：检查提示词拼接点（grep 模板字符串进 prompt 的位置逐个人工过）；
4. **红队演练**（上线前）：把自己当攻击者——套系统提示、喂间接注入页面、诱导高危工具、
   刷预算边界；产出物是"攻破记录 + 修复 + 对抗用例"，进入下一轮回归。

## 5. 审计报告模板（每次审计的产出物）

> 产出物对齐本库交付规范（诚实第一，P0/P1/P2 分级，见 `../../vbcoding全流程/03-支撑资产/审阅报告模板.md`）。

- 威胁建模图（数据流 + 信任边界标注）
- 检查单（第 2 节）逐项：通过 / 未通过（P0-P2 定级）/ 不适用（说明）
- 对抗用例集：本轮新增 N 条，结果全绿 / 未绿（清单）
- 攻破记录：攻击路径复现步骤 + 修复 + 回归验证
- 遗留风险：明确"带着哪些已知风险上线"，由人签字
